## D002 用 Electron

- **日期**：2026-10-22
- **狀態**：已定案

> 使用者：「會選Electron是因為已經有用來做一個遊戲 然後vscode也是這樣做的樣子」

**決定**：Electron ＋ 純 JS／HTML。

**為什麼**：使用者做過 Electron（`block-builders/其他版本/ElectronVer`）；VS Code 也是 Electron。
要讀寫本機資料夾、監看檔案變動，之後還要全域快捷鍵、系統匣，Electron 都有。

**沒採用的做法**：
- 純 HTML ＋ File System Access API：不用安裝，但不能常駐、不能全域快捷鍵，資料夾權限可能要重新授權，沒有穩定的檔案監看。
- Tauri：比較輕，但建置要裝 Rust 工具鏈。
- Obsidian ＋ 外掛：一樣是讀寫資料夾裡的 md。使用者選擇自己做；Obsidian 做不做得到代號自動關聯、匯入舊 txt 這些，沒有實際比較過（未驗證）。

**影響**：安全設定——檔案操作只放在 main process，畫面透過 preload ＋ `contextBridge` 呼叫；
`nodeIntegration` 關、`contextIsolation` 開。

**後續**：
- 2026-10-22：使用者：「可以安裝 Electron」。裝了 electron 45.0.0（`devDependencies` 寫 `^45.0.0`）。
  Electron 45 的執行檔不是 `npm install` 時下載，是第一次 `require('electron')` 才下載
  （`node_modules/electron/index.js` L25～L49）。當天手動觸發一次，公司網路抓得到，`electron.exe --version` 回 `v45.0.0`。

## D003 不用資料庫，啟動時全部讀進記憶體

- **日期**：2026-10-22
- **狀態**：提案
- **相關**：D004

**決定**：不用 SQLite 之類的資料庫。啟動時掃 `data/` 全部讀進記憶體建索引，搜尋直接掃。

**為什麼**：舊紀錄 2025/12/29～2026/10/22 共 189 天、779 筆條目（`每日工作紀錄2026.txt` 2026-10-22 實測，
「沒縮排、不是日期、不是 `---`」的行數），一年不到一千筆。

**沒採用的做法**：SQLite——檔案被外部改了（人或 Claude 直接編輯每日檔）還要同步回資料庫，多一層出錯的地方，量也用不到。

**影響**：哪天量到啟動變慢，再考慮快取索引。

## D040 打包成單一可攜 exe：electron-builder，`pack.cmd` 一鍵打包到 dist\

- **日期**：2026-10-22
- **狀態**：已定案
- **相關**：D002、D016、D038、D039

> 使用者：「做一個cmd可以打包出exe結果」
>
> 使用者（Claude 問三題）：打包方式選「單一可攜 exe（裝 electron-builder）」（另兩個是「資料夾版，不裝新套件」「安裝程式」）；
> 資料位置選「照現在：第一次開跳視窗選」（另一個是「預設放 exe 旁邊的 data 資料夾」）；輸出位置選「daybook\dist\（不進 git）」

**決定**：
- 裝 **electron-builder**（devDependency，26.15.3）；`package.json` 的 `build`：portable、圖示 `assets/icon.ico`（D038）、
  只打包 `src/`、`assets/`、`package.json`（測試、文件、`node_modules` 都不進去）、產出 `dist\daybook-版本號.exe`。
- **`pack.cmd`**：點兩下或打 `pack`；沒裝套件先 `npm install`、清掉舊的 `dist\`、`npm run dist`；`pack nopause` 做完不停下來。
- 資料資料夾照 D016：第一次開跳視窗選、記在 `%APPDATA%\daybook\settings.json`，跟 `npm start`（不帶 `--data-dir`）用同一份設定。
- `.gitignore` 加 `dist/`；`.gitattributes` 讓 `*.cmd` 一律 CRLF（LF 的 cmd 檔，`goto`／`call :標籤` 可能跳錯）。

**為什麼**：
- 資料夾版不用裝套件，但 exe 檔案本身的圖示換不掉（要另外的工具）；使用者選單一 exe。
- 量到的（2026-10-22）：Electron 本體 357MB（73 個檔）、程式本身約 500KB；打包出來的 exe **97.1MB**。

**沒採用的做法**：
- 資料夾版（複製 Electron 改名）、安裝程式：使用者選可攜 exe。
- 資料預設放 exe 旁邊：可攜 exe 每次開都解壓到暫存區，「exe 旁邊」要另外處理；使用者選照現在。

**影響**：
- 可攜 exe **每次開都先解壓到暫存區**：實測開到看到視窗 6.8～10.6 秒（`npm start` 約 1～2 秒）；正常關視窗後啟動器會把解壓的檔清掉（強制結束就會留在 `%TEMP%`）。
- 沒有程式碼簽章：第一次開 Windows 可能跳 SmartScreen 警告。
- 安裝時 npm 報 8 個 moderate 弱點（都在開發用套件，不進 exe）；沒跑 `npm audit fix`（會自動改版本）。
- `electron-winstaller` 的安裝腳本被 npm 擋下沒跑：那是另一種安裝程式格式用的，portable 用不到。
- 檢查方式（沒放進自動測試，打包有改再照做）：exe 檔案版本＝package.json、`asar list` 只有 src／assets／package.json、
  用 `--data-dir` 指 fixture 複本開起來看視窗標題與圖示、`%APPDATA%\daybook` 沒被建、正常關掉後暫存區沒殘留。

**實測**（2026-10-22）：照上面的檢查方式做過：檔案版本 1.1.0、產品名稱 daybook；視窗標題 `daybook 1.1.0`；
exe 檔案圖示、視窗圖示都是樹懶；`%APPDATA%\daybook` 沒被建；正常關視窗後啟動器 exit 0、解壓的資料夾清掉了。

**後續**：
- 2026-10-22：使用者要可攜版、安裝版兩個都打；`pack.cmd` 不再整個刪 `dist\` → 見 D043。

## D043 可攜版、安裝版兩個都打；pack.cmd 只清打包產生的東西

- **日期**：2026-10-22
- **狀態**：已定案（兩個都打是使用者選的）；檔名、清法是 Claude 提的
- **相關**：D040、D041

> 使用者：「安裝版有什麼差別?」
>
> 使用者（Claude 列差別後問要不要換）：選「兩個都打」（另兩個是「維持可攜版」「改成安裝版」）

**決定**：
- `build.win.target` 改成 `portable`、`nsis` 兩個；產出 `dist\daybook-版本號-portable.exe`、`dist\daybook-版本號-setup.exe`。
- 安裝版用 electron-builder 的預設：一鍵安裝、只裝給目前使用者（不用管理員權限）、建桌面與開始選單捷徑、裝完自動開、解除安裝不刪設定
  （預設值是從本機 `node_modules\app-builder-lib\scheme.json` 讀的）。
- **`pack.cmd` 只清打包產生的東西**（`win-unpacked\`、`daybook-*.exe`、`*.blockmap`、`builder-*.yml`、`latest*.yml`），`dist\` 裡其他東西不動。

**為什麼**：
- 只清打包產生的東西：使用者試 1.1.0 時曾把紀錄資料夾選在 `dist\data`（見 D041 的證據）。原本 `pack.cmd` 會 `rmdir /s /q dist`——
  整個刪掉、不進資源回收筒，那時要是有紀錄就救不回來。這次是使用者自己先丟進資源回收筒（0 位元組），沒有損失。

**影響**：
- 安裝版**沒有實際裝過**（會在使用者電腦建捷徑、寫解除安裝資訊），只驗了檔案版本、圖示；第一次請使用者自己裝。
- 實測量的：可攜版 97.1MB、安裝檔 97.5MB，檔案版本 1.2.0、產品名稱 daybook，exe 圖示都是樹懶；
  可攜版用 `--data-dir` 開：視窗標題 `daybook 1.2.0`、開到看到視窗 7.8 秒、正常關掉後解壓的檔清掉。
- 驗過 `pack.cmd` 不會刪到 `dist\` 裡別的東西：先放一個測試資料夾進 `dist\` 再打包，打完還在。
