## D002 用 Electron

- **日期**：2026-10-22
- **狀態**：已定案

> 使用者：「會選Electron是因為已經有用來做一個遊戲 然後vscode也是這樣做的樣子」

**決定**：Electron ＋ 純 JS／HTML。

**為什麼**：使用者做過 Electron（`block-builders/其他版本/ElectronVer`）；VS Code 也是 Electron。
要讀寫本機資料夾、監看檔案變動，之後還要全域快捷鍵、系統匣，Electron 都有。

**沒採用的做法**：
- 純 HTML ＋ File System Access API：不用安裝，但不能常駐、不能全域快捷鍵，資料夾權限可能要重新授權，沒有穩定的檔案監看。
- Tauri：比較輕，但建置要裝 Rust 工具鏈。
- Obsidian ＋ 外掛：一樣是讀寫資料夾裡的 md。使用者選擇自己做；Obsidian 做不做得到代號自動關聯、匯入舊 txt 這些，沒有實際比較過（未驗證）。

**影響**：安全設定——檔案操作只放在 main process，畫面透過 preload ＋ `contextBridge` 呼叫；
`nodeIntegration` 關、`contextIsolation` 開。

**後續**：
- 2026-10-22：使用者：「可以安裝 Electron」。裝了 electron 45.0.0（`devDependencies` 寫 `^45.0.0`）。
  Electron 45 的執行檔不是 `npm install` 時下載，是第一次 `require('electron')` 才下載
  （`node_modules/electron/index.js` L25～L49）。當天手動觸發一次，公司網路抓得到，`electron.exe --version` 回 `v45.0.0`。

## D003 不用資料庫，啟動時全部讀進記憶體

- **日期**：2026-10-22
- **狀態**：提案
- **相關**：D004

**決定**：不用 SQLite 之類的資料庫。啟動時掃 `data/` 全部讀進記憶體建索引，搜尋直接掃。

**為什麼**：舊紀錄 2025/12/29～2026/10/22 共 189 天、779 筆條目（`每日工作紀錄2026.txt` 2026-10-22 實測，
「沒縮排、不是日期、不是 `---`」的行數），一年不到一千筆。

**沒採用的做法**：SQLite——檔案被外部改了（人或 Claude 直接編輯每日檔）還要同步回資料庫，多一層出錯的地方，量也用不到。

**影響**：哪天量到啟動變慢，再考慮快取索引。

## D040 打包成單一可攜 exe：electron-builder，`pack.cmd` 一鍵打包到 dist\

- **日期**：2026-10-22
- **狀態**：已定案
- **相關**：D002、D016、D038、D039

> 使用者：「做一個cmd可以打包出exe結果」
>
> 使用者（Claude 問三題）：打包方式選「單一可攜 exe（裝 electron-builder）」（另兩個是「資料夾版，不裝新套件」「安裝程式」）；
> 資料位置選「照現在：第一次開跳視窗選」（另一個是「預設放 exe 旁邊的 data 資料夾」）；輸出位置選「daybook\dist\（不進 git）」

**決定**：
- 裝 **electron-builder**（devDependency，26.15.3）；`package.json` 的 `build`：portable、圖示 `assets/icon.ico`（D038）、
  只打包 `src/`、`assets/`、`package.json`（測試、文件、`node_modules` 都不進去）、產出 `dist\daybook-版本號.exe`。
- **`pack.cmd`**：點兩下或打 `pack`；沒裝套件先 `npm install`、清掉舊的 `dist\`、`npm run dist`；`pack nopause` 做完不停下來。
- 資料資料夾照 D016：第一次開跳視窗選、記在 `%APPDATA%\daybook\settings.json`，跟 `npm start`（不帶 `--data-dir`）用同一份設定。
- `.gitignore` 加 `dist/`；`.gitattributes` 讓 `*.cmd` 一律 CRLF（LF 的 cmd 檔，`goto`／`call :標籤` 可能跳錯）。

**為什麼**：
- 資料夾版不用裝套件，但 exe 檔案本身的圖示換不掉（要另外的工具）；使用者選單一 exe。
- 量到的（2026-10-22）：Electron 本體 357MB（73 個檔）、程式本身約 500KB；打包出來的 exe **97.1MB**。

**沒採用的做法**：
- 資料夾版（複製 Electron 改名）、安裝程式：使用者選可攜 exe。
- 資料預設放 exe 旁邊：可攜 exe 每次開都解壓到暫存區，「exe 旁邊」要另外處理；使用者選照現在。

**影響**：
- 可攜 exe **每次開都先解壓到暫存區**：實測開到看到視窗 6.8～10.6 秒（`npm start` 約 1～2 秒）；正常關視窗後啟動器會把解壓的檔清掉（強制結束就會留在 `%TEMP%`）。
- 沒有程式碼簽章：第一次開 Windows 可能跳 SmartScreen 警告。
- 安裝時 npm 報 8 個 moderate 弱點（都在開發用套件，不進 exe）；沒跑 `npm audit fix`（會自動改版本）。
- `electron-winstaller` 的安裝腳本被 npm 擋下沒跑：那是另一種安裝程式格式用的，portable 用不到。
- 檢查方式（沒放進自動測試，打包有改再照做）：exe 檔案版本＝package.json、`asar list` 只有 src／assets／package.json、
  用 `--data-dir` 指 fixture 複本開起來看視窗標題與圖示、`%APPDATA%\daybook` 沒被建、正常關掉後暫存區沒殘留。

**實測**（2026-10-22）：照上面的檢查方式做過：檔案版本 1.1.0、產品名稱 daybook；視窗標題 `daybook 1.1.0`；
exe 檔案圖示、視窗圖示都是樹懶；`%APPDATA%\daybook` 沒被建；正常關視窗後啟動器 exit 0、解壓的資料夾清掉了。

**後續**：
- 2026-10-22：使用者要可攜版、安裝版兩個都打；`pack.cmd` 不再整個刪 `dist\` → 見 D043。

## D043 可攜版、安裝版兩個都打；pack.cmd 只清打包產生的東西

- **日期**：2026-10-22
- **狀態**：已定案（兩個都打是使用者選的）；檔名、清法是 Claude 提的
- **相關**：D040、D041

> 使用者：「安裝版有什麼差別?」
>
> 使用者（Claude 列差別後問要不要換）：選「兩個都打」（另兩個是「維持可攜版」「改成安裝版」）

**決定**：
- `build.win.target` 改成 `portable`、`nsis` 兩個；產出 `dist\daybook-版本號-portable.exe`、`dist\daybook-版本號-setup.exe`。
- 安裝版用 electron-builder 的預設：一鍵安裝、只裝給目前使用者（不用管理員權限）、建桌面與開始選單捷徑、裝完自動開、解除安裝不刪設定
  （預設值是從本機 `node_modules\app-builder-lib\scheme.json` 讀的）。
- **`pack.cmd` 只清打包產生的東西**（`win-unpacked\`、`daybook-*.exe`、`*.blockmap`、`builder-*.yml`、`latest*.yml`），`dist\` 裡其他東西不動。

**為什麼**：
- 只清打包產生的東西：使用者試 1.1.0 時曾把紀錄資料夾選在 `dist\data`（見 D041 的證據）。原本 `pack.cmd` 會 `rmdir /s /q dist`——
  整個刪掉、不進資源回收筒，那時要是有紀錄就救不回來。這次是使用者自己先丟進資源回收筒（0 位元組），沒有損失。

**影響**：
- 安裝版**沒有實際裝過**（會在使用者電腦建捷徑、寫解除安裝資訊），只驗了檔案版本、圖示；第一次請使用者自己裝。
- 實測量的：可攜版 97.1MB、安裝檔 97.5MB，檔案版本 1.2.0、產品名稱 daybook，exe 圖示都是樹懶；
  可攜版用 `--data-dir` 開：視窗標題 `daybook 1.2.0`、開到看到視窗 7.8 秒、正常關掉後解壓的檔清掉。
- 驗過 `pack.cmd` 不會刪到 `dist\` 裡別的東西：先放一個測試資料夾進 `dist\` 再打包，打完還在。

**後續**：
- 2026-10-27：安裝版第一次實際裝、解除安裝過（1.6.1，使用者同意後） → 見 D050〈後續〉。

## D050 不留沒用的檔：可攜版啟動時清掉當掉留下的解壓資料夾；解除安裝時刪掉安裝程式的備份

- **日期**：2026-10-27
- **狀態**：已定案（兩件都是使用者要的）；怎麼認、怎麼避開正在用的是 Claude 提的
- **相關**：D040、D043、D048、D049

> 使用者（看說明頁）：「每次開都先解壓到 C:\Users\cm8\AppData\Local\Temp\<每一版不同的名稱>，正常關掉會自動刪；當掉或被強制結束就會留下，可以直接刪。 ->程式啟動時去檢查 不要殘留沒用的檔案」
>
> 使用者：「裝的時候，安裝程式會把自己複製一份放在 C:\Users\cm8\AppData\Local\daybook-updater（約 97MB）。解除安裝不會刪。->這能解除安裝也刪掉嗎?」

**決定**：
- **可攜版殘留**（`src/main/cleanup.js`）：打包後的 daybook（可攜版、安裝版都算）開好視窗後，掃 `%TEMP%` 第一層：
  - 認得出來才刪：名稱是 27 碼英數（electron-builder `generateKsuid`）、裡面有 `daybook.exe` 和 `resources\app.asar`。
  - 跳過：正在跑的這一份（`process.execPath` 的資料夾）；有 daybook 正從那裡跑著的（`daybook.exe` 用寫入模式打不開＝在跑）。
  - 刪的順序：`daybook.exe` 以外的先刪、`daybook.exe` 最後；中途刪不動，exe 還在，下次還認得出來再清。出錯不擋啟動。
  - 用 `original-fs` 刪：一般的 `fs` 在 Electron 裡會把 `app.asar` 當資料夾。
  - 開發（沒打包）不清：e2e、`npm start` 不去動這台電腦的暫存區。
- **安裝程式的備份**（`build\installer.nsh`）：`customUnInstall` 裡 `RMDir /r "$LOCALAPPDATA\daybook-updater"`；升級時（舊版的解除安裝帶 `--updated`）不刪。
- 說明頁跟著改寫：可攜版「當掉留下的，下次開 daybook 時會自動清掉」；安裝版「解除安裝時會一起刪掉（1.6.0 以前的安裝檔不會）」；完全移除的步驟跟著改。

**為什麼**（實測、讀碼）：
- 可攜版啟動器開始時會先刪自己的解壓資料夾再解壓（`portable.nsi` 的 `RMDir /r $INSTDIR`），所以同一版當掉的殘留下次開同一版就會被蓋掉；
  會一直留著的是**別的版本**的（每一版名稱不同），所以要 daybook 自己掃。
- 不能用「改名資料夾」判斷有沒有在用：實測 exe 跑著時改名資料夾會成功。也不能直接刪：實測會刪到一半（沒被佔用的先刪掉），會把別的版本正在跑的弄壞。
  用寫入模式打開 exe：跑著時 EBUSY、沒跑時打得開、打開不改內容（2026-10-27 拿 PING.EXE 實測）。
- 安裝程式的備份：electron-builder 的解除安裝裡沒有刪它的步驟（D048 查的）；`build\installer.nsh` 會自動被加進安裝檔（`NsisTarget.js` 的 `getResource(options.include, "installer.nsh")`，預設資料夾 `build`），
  `customUnInstall` 在解除安裝一開始執行（`uninstaller.nsh`）；makensis 帶 `-INPUTCHARSET UTF8`，中文註解沒問題。

**沒採用的做法**：
- 打包設定固定解壓資料夾名稱（`portable.unpackDirName`），讓每一版都用同一個、啟動器自己清：清不到 1.6.0 以前留下的；而且開第二份時啟動器會先刪正在跑的那份的資料夾。
- 清之前跳視窗問：使用者要的是「不要殘留」，殘留是程式自己的暫存，不是使用者的資料。
- 解除安裝順便刪 `%APPDATA%\daybook`：使用者這次只問備份那個；設定與快取要不要一起刪還沒決定（〈還沒決定的事〉）。

**實測**（2026-10-27，打包到暫存資料夾，沒動 `dist\`）：
- 打包成功、`builder-debug.yml` 有 `!include "…\build\installer.nsh"`。
- 可攜版 1.6.0 用 `--data-dir` 開：開之前在 `%TEMP%` 造的假殘留開起來就不見；這次解壓的資料夾沒被自己清掉；說明頁可攜版標「你現在用的」、exe 與解壓位置正確；正常關掉後啟動器 exit 0、解壓的資料夾不見。
- parser C1（清理規則，含正在跑的不動）；故意拿掉「正在用就跳過」，C1 會紅。
- **安裝、解除安裝沒有實際做**（會在使用者電腦建捷徑、寫登錄檔），`daybook-updater` 解除安裝會不會真的刪掉還沒驗。

**影響**：
- 新增 `src/main/cleanup.js`、`build\installer.nsh`；`main.js` 開好視窗後呼叫；`index.html` 說明頁的字。
- electron-builder 改版時：解壓資料夾的命名規則、備份資料夾的名稱、`customUnInstall` 的掛法要重查。
- 測試 C1；打包後的 exe 手動檢查多三條（`e2e測試.md`）。

**後續**：
- 2026-10-27：說明頁拿掉「1.6.0 以前的安裝檔不會刪，要自己刪」那兩處。
  > 使用者：「1.6.0 以前的安裝檔沒有這一步。說明頁已經寫清楚-> 不用寫 現在還是開發階段」

  規矩：**還在開發階段，畫面上不寫舊版本的差別**（沒有人在用舊版）；舊版的差別只記在開發筆記。

## D053 點兩下就開：專案根目錄的 daybook.cmd，直接叫 Electron 起來

- **日期**：2026-10-27
- **狀態**：已定案（放專案根目錄是使用者選的）；檔名、怎麼叫起來是 Claude 定的
- **相關**：D016、D030、D040

> 使用者：「幫我做個cmd可以點下去就開來看」
>
> 使用者（Claude 問放專案根目錄還是桌面）：選「專案根目錄」

**決定**：`daybook.cmd` 跟 `pack.cmd` 放一起。開法跟 `npm start` 一樣（設定檔裡的紀錄資料夾），但不經過 npm：
`start "" node_modules\electron\dist\electron.exe .`，叫起來 cmd 就結束。沒裝套件先 `npm install`；Electron 執行檔還沒下載先跑 `node_modules\electron\install.js`。

**為什麼**：
- `npm start` 是 `electron .`，`node_modules\electron\cli.js` 會 spawn `dist\electron.exe` 再等它關掉，黑色視窗會一直開著；直接 `start` 執行檔就不用等。
- Electron 45 沒有 postinstall，執行檔是第一次 `require('electron')` 時才下載（`node_modules\electron\index.js` 的 `downloadElectron` 跑 `install.js`），直接叫執行檔就要自己先補。
- 不叫 `start.cmd`：在命令列打 `start` 跑的是 cmd 內建的 `start`，不是這個檔（2026-10-27 實測：資料夾裡放 `start.cmd`、打 `start /?` 印出的是內建說明）。

**實測**（2026-10-27）：
- daybook 已經開著時跑 `daybook.cmd`：98ms 結束、exit 0，沒有多開視窗；先把開著的縮到工作列再跑，被還原了（D030 的 `second-instance`）＝真的叫起了同一個 app。
- **沒測**：沒開著時從頭開（使用者的 daybook 正開著，沒去關它）；沒裝套件、沒下載執行檔那兩段。
- 這個工具環境設了 `NoDefaultCurrentDirectoryInExePath=1`，在這裡 `cmd /c daybook.cmd` 找不到檔，要寫 `.\daybook.cmd`；點兩下、一般的 cmd 不受影響。

**影響**：`daybook.cmd`（CRLF，`.gitattributes`）；README〈檔案〉〈怎麼跑〉。
