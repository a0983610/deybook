## D002 用 Electron

- **日期**：2026-10-22
- **狀態**：已定案

> 使用者：「會選Electron是因為已經有用來做一個遊戲 然後vscode也是這樣做的樣子」

**決定**：Electron ＋ 純 JS／HTML。

**為什麼**：使用者做過 Electron（`block-builders/其他版本/ElectronVer`）；VS Code 也是 Electron。
要讀寫本機資料夾、監看檔案變動，之後還要全域快捷鍵、系統匣，Electron 都有。

**沒採用的做法**：
- 純 HTML ＋ File System Access API：不用安裝，但不能常駐、不能全域快捷鍵，資料夾權限可能要重新授權，沒有穩定的檔案監看。
- Tauri：比較輕，但建置要裝 Rust 工具鏈。
- Obsidian ＋ 外掛：一樣是讀寫資料夾裡的 md。使用者選擇自己做；Obsidian 做不做得到代號自動關聯、匯入舊 txt 這些，沒有實際比較過（未驗證）。

**影響**：安全設定——檔案操作只放在 main process，畫面透過 preload ＋ `contextBridge` 呼叫；
`nodeIntegration` 關、`contextIsolation` 開。

**後續**：
- 2026-10-22：使用者：「可以安裝 Electron」。裝了 electron 45.0.0（`devDependencies` 寫 `^45.0.0`）。
  Electron 45 的執行檔不是 `npm install` 時下載，是第一次 `require('electron')` 才下載
  （`node_modules/electron/index.js` L25～L49）。當天手動觸發一次，公司網路抓得到，`electron.exe --version` 回 `v45.0.0`。

## D003 不用資料庫，啟動時全部讀進記憶體

- **日期**：2026-10-22
- **狀態**：提案
- **相關**：D004

**決定**：不用 SQLite 之類的資料庫。啟動時掃 `data/` 全部讀進記憶體建索引，搜尋直接掃。

**為什麼**：舊紀錄 2025/12/29～2026/10/22 共 189 天、779 筆條目（`每日工作紀錄2026.txt` 2026-10-22 實測，
「沒縮排、不是日期、不是 `---`」的行數），一年不到一千筆。

**沒採用的做法**：SQLite——檔案被外部改了（人或 Claude 直接編輯每日檔）還要同步回資料庫，多一層出錯的地方，量也用不到。

**影響**：哪天量到啟動變慢，再考慮快取索引。
