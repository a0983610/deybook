# 輸出

這個主題的決定。索引與寫法見 `開發筆記.md`。

## D010 輸出單一文件有兩種切法

- **日期**：2026-10-22
- **狀態**：已定案（要做）；格式定了、日期區間做了（見〈後續〉）；依代號或主題還沒做
- **相關**：D007、D035

> 使用者：「也能靠這工具轉換單一文件 或做出事件的關聯」

**決定**：第二版做，兩種切法——
- 依日期區間：還原成舊 txt 那樣的流水帳（寫週報、月報用）。
- 依代號或主題：某件事從頭到尾的歷程（交接、檢討用）。

**後續**：
- 2026-10-22：使用者選了格式 **Markdown**（不是舊 txt 寫法）、範圍「日期區間」＋「全部」；「目前看到的結果」（依代號、搜尋）這次沒選 → 見 D035。

## D035 匯出成一份 Markdown：起訖日期或全部，存檔視窗選位置

- **日期**：2026-10-22
- **狀態**：已定案（範圍、格式、選日期的方式是使用者選的）；Markdown 的細節寫法是 Claude 提的
- **相關**：D009、D010、D016、D025

> 使用者：「增加黑暗模式 可以參考vscode 匯出成單一檔案功能」
>
> 使用者（Claude 問範圍／格式／選日期，選項附範例）：範圍選「日期區間」「全部」（沒選「目前看到的結果」）；
> 格式選「Markdown」（另兩個是「txt，跟舊記事本一樣」「HTML」）；選日期選「只要起訖兩格日期」（另兩個是「快速鈕＋自訂」「在左邊日期清單選」）

**決定**：
- 標題列「**匯出…**」打開一列：起、訖兩格日期（含頭尾，預設這週一到今天）、「**匯出這段**」「**匯出全部**」。再按一次「匯出…」收起來。
- 按了跳 Windows 存檔視窗選位置（預設下載資料夾、檔名 `工作紀錄_起_訖.md`／`工作紀錄_全部_今天.md`；同一次開著會記住上次存的資料夾）。
- 「全部」從第一天到最後一天，最後接 `## 待處理`（含隱藏的，標 `[隱藏]`）。
- 寫法（`src/shared/export.js`）：
  - `# 工作紀錄 起 ～ 訖`；每天 `## 2026-01-21（三）`；每筆 `### 標題`，內容一行一項 `- …`。沒寫東西的日子不列。
  - 好幾行標題共用內容的（D009）用「 / 」接成一行；狀態照寫 `[待回覆]`；事件編號 `^N` 不寫（是工具內部串東西用的）。
  - 內容多的縮排變下一層清單；開頭的 `->` 變 `→ `。
  - 開頭會被 Markdown 當語法的（`1. `、`- `、`# `、`> `）前面加 `\`，照原字顯示；`1.控管` 這種點後面沒空白的本來就不算，不動。
- 起日晚於訖日、那段沒有紀錄：跳提示、不寫檔。

**為什麼**：
- 預設「這週一到今天」：「週報」一直放在待處理，寫週報最常用。
- 舊檔裡內容以 `1. ` 開頭的有好幾段（12/30 那筆就 4 行），不跳脫的話 Markdown 會重新編號、跟原文不一樣。
- 真資料（舊檔 189 天）匯出全部：3350 行、117KB、約 5ms；日期數、每筆標題數、每行內容數都跟原檔一樣（R4）。

**沒採用的做法**：
- txt（舊記事本寫法）、HTML：使用者選 Markdown。
- 快速鈕（這週、上週……）、在日期清單選範圍：使用者選只要兩格日期。
- 存檔視窗之外，另外記住上次的資料夾到設定檔：只在這次開著時記；--data-dir 時不讀寫設定檔（D016）。

**影響**：
- `src/shared/export.js`（純函式）；`main.js` 的 `exportMd`、`export`；`preload.js` 的 `exportMd`；`app.js` 的匯出列；`index.html` 的 `#exportBar`。
- **`--export-dir <資料夾>`**：只給測試用，匯出不跳存檔視窗、直接寫進那個資料夾（原生存檔視窗 CDP 點不到）。
- 測試 X1、R4、E31。

**實測**（2026-10-22）：parser 152 條、e2e 111 條全過；拿舊檔匯出全部看過長相（`1\. ` 跳脫、多層清單、待處理在最後）。

**後續**：
- 2026-10-27：匯出改成能匯回來（每行標題一個 `###`、`^編號` 照寫、內容原文照抄，不改 `->`、不跳脫），`export.js` 搬到 `formats/daybook-md.js` → 見 D046
- 2026-10-28：匯出列加格式的下拉選單（Markdown、Excel、擴充的），`exportMd` 拆成 `exportRange`／`exportFile`，存檔視窗的副檔名照格式 → 見 D078。

## D046 匯出的 Markdown 就是標準匯出入格式：匯出再匯回，卡片一模一樣

- **日期**：2026-10-27
- **狀態**：已定案（用現在的 MD 當標準格式、標題寫出 `^N`、細節交給 Claude 定，是使用者說的）；細節寫法是 Claude 定的
- **相關**：D008、D009、D022、D035、D044、D047

> 使用者：「匯入匯出 要相同格式 能把匯出檔案再次匯入」
>
> 使用者：「標準匯出入 格式就用現在的MD」
>
> 使用者（Claude 問匯出標題多出 `^N` 可不可以）：「匯出的標題多出 ^N 可以(匯出入標準格式你決定就好 沒打算給人看)」

**決定**：
- 匯出（`formats/daybook-md.js` 的 `toMarkdown`）：
  - 每一行標題各寫一個 `### 原文`，`^編號`、`[隱藏]`、`[狀態]` 都照原文寫。共用內容的好幾行標題（D009）連著寫、中間不空行；不同筆之間空一行。
  - 內容：第一層縮排拿掉，後面多的 Tab 變下一層清單，其他字原樣照抄（`->` 不改成 `→`、開頭不加 `\` 跳脫）。
  - `# 標題`、`## 2026-01-21（三）`、`## 待處理`、`（沒有）` 照舊。
- 匯入（同一個檔的 `parse`）是反方向：`### ` 後面整行是標題原文、`- ` 後面整行是內容原文（前面補一個 Tab，清單每深一層多一個 Tab）；筆跟筆之間補一個空行。
  認不得的行、第一個日期之前就有內容、同一天兩次、不存在的日期、`## 待處理` 兩次、標題會被當成內容（空白或「數字＋.」開頭）、清單沒有字：報錯寫第幾行，不猜（同 D018）。星期不看。
- **保證**：匯出再匯回，卡片一模一樣（標題原文、內容、狀態、隱藏、`^編號`、哪幾行共用內容）。
  會變的只有不影響卡片的：第一層的空白縮排變 Tab（D008）、內容中間的空行拿掉、沒縮排的「1.」內容（D008）前面多一個 Tab。

**為什麼**：
- 原本的匯出匯不回去：`^N` 不寫；共用內容的標題用「 / 」接成一行，標題本身有「 / 」就分不出來；`->` 一律變 `→ `，舊檔 L596 `-> 施工中` 的空白會掉；內容開頭的 `\` 分不出是原文還是跳脫加的。
- 用「每行標題一個 `###`＋空行分筆」，不用「 / 」：parser 分共用內容是看光頭標題有沒有連著，空行會打斷（D009，`parser.js` 的 `parseDay`）。
  只要匯回的標題行順序、連不連著跟原本一樣，D009 算出來就一樣，不用另外記哪幾行共用，標題裡有「 / 」也不怕。
- 不改 `->`、不跳脫：檔案不是給人看的（使用者說的），原文照抄最不會出錯。舊檔裡原文就以 `→`、`\` 開頭的內容 0 行（grep 量的），但新寫的可能有，跳脫規則一多就有還原不回來的邊角。
- 實測（2026-10-27）：舊檔（只讀）189 天、642 張卡、待處理，匯出再匯回全部一樣（parser R6）；邊角寫法 X2；從畫面匯進空資料夾 E39。

**沒採用的做法**：
- 每天的原文整段照抄進 MD（位元組都一樣）：標題行可能剛好以 `## ` 開頭，跟日期標題分不出來，還是要跳脫；使用者要用現在的 MD。
- 保留「 / 」接標題、再加跳脫：多一套規則，換來的只是 Markdown 預覽好看，檔案又不給人看。
- `^N` 藏在 `<!-- ^3 -->`：使用者說可以直接寫。

**影響**：
- `src/shared/export.js` 搬到 `src/shared/formats/daybook-md.js`：匯出、匯入寫在同一個檔，改一邊要看另一邊。`main.js`、測試的 require 跟著改。
- 1.4.0 以前匯出的檔也匯得進來，但 `^N` 本來就沒寫，共用內容的標題會變成一行「A / B」，`->` 會是 `→ `。
- 匯進來的 `^N` 照原號碼寫：拿自己的匯出還原沒問題；匯進另一個資料夾、那裡剛好用了同樣的號碼，兩件不相干的事會被串在一起。先不處理（2026-10-27 跟使用者說過）。
- 測試 X1（改）、X2、X3、M1（加匯出檔）、R4（改）、R6、E39。

**後續**：
- 2026-10-28：匯出做成外掛，daybook Markdown 變成內建匯出格式的其中一種（`write`），排出來一字不差 → 見 D078

## D078 匯出也做成外掛：內建 Markdown、Excel，擴充可以加任何格式；下拉選單選格式；「匯入格式」頁改名「格式」

- **日期**：2026-10-28
- **狀態**：已定案（匯出做成跟匯入一樣的外掛、Excel 內建且自己寫不裝套件、下拉選單、頁面改名「格式」一頁列兩種，是使用者說的、選的）；
  介面（`write`、`data` 的欄位、key）、Excel 的欄位細節（凍結、篩選、日期格式、隱藏寫「是」、沒分類寫「未分類」）、範例擴充也能匯出、先跑再跳存檔視窗是 Claude 定的
- **相關**：D010、D025、D035、D046、D047、D055、D056、D079

> 使用者：「匯出也像匯入一樣 做夠外掛功能去改變產出格式 最好是也因此能產成EXCEL或任何其他想要的格式」
>
> 使用者（Claude 問四件事後選的）：Excel 選「內建 .xlsx，自己寫」（另兩個是「裝 Excel 套件」「只做 CSV」；選項附了一筆一列的版面）；
> 選格式選「下拉選單」（另一個是「一排格式鈕」）；頁面選「改名『格式』，一頁列兩種」（另兩個是「名稱不改」「另開『匯出格式』頁」）；
> 「請 AI 寫」選「這次一起做」（見 D079）

**決定**：
- **匯出格式的介面**：`{ id, label, hint, extension（副檔名，不含「.」）, write(data) → 字串或 Uint8Array }`。內建的登記在 `formats/index.js` 的 `EXPORT_FORMATS`：
  daybook Markdown（`daybook-md.js` 的 `write`，排法同 `toMarkdown`）、Excel（`xlsx.js`）。第一個是下拉選單沒選過時的預設。
- **`data`**（`formats/index.js` 的 `exportData`）：`title`、`from`、`to`、`all`；`days: [{ date, weekday, text（原文）, entries }]`（沒寫東西的日子不列）；
  `todo: { text, entries }`（匯出全部才有）。`entries` 是 `parseDay` 拆好的每一筆，只留給格式用的欄位：
  `heads`（原文）、`title`、`body`（第一層縮排拿掉）、`status`、`hidden`、`flagged`、`flagCat`、`event`、`codes`、`types`、`people`、`tickets`、`topics`。
- **擴充**：`package.json` 的 `contributes.exportFormats: [{ id, label, hint, extension }]`，程式檔 `formats[id].write`。同一個 id 可以同時列在 `importFormats`
  （同一種格式能匯入也能匯出，範例就是）。`importFormats`、`exportFormats` 至少一種。啟用照舊一個擴充一次（D055），兩邊一起。
- **匯出**：下拉選單的值是 key（內建是 id，擴充是「擴充名稱/格式 id」）→ `exportRange`（日期區間或全部，同 D035）→ 內建的直接跑、擴充的在擴充程序跑
  （`ext-host.js` 多一個 `write`，同樣 10 秒、丟錯寫是哪個擴充）→ **跑完才跳存檔視窗**（標題、副檔名篩選照格式）→ 字串用 UTF-8 寫、位元組照寫。
- **下拉選單**：「匯出」後面、日期前面。每次打開匯出列重讀（擴充啟用、停用了就跟著變）；選過的記在這台電腦（`localStorage` 的 `daybook.exportFormat`），那個格式不在了就用第一個。
  選項寫「名稱（.副檔名）」，擴充的多寫「，擴充「名稱」」；滑鼠停著看 hint。
- **Excel**（`xlsx.js`）：工作表「工作紀錄」一筆一列：日期｜星期｜標題｜內容｜狀態｜標記｜事件｜代號；匯出全部多一張「待處理」：標題｜內容｜狀態｜隱藏。
  - 日期存成 Excel 的日期（1899-12-30 起算），格式 `yyyy-mm-dd`：Excel 的篩選、排序照日期走。事件編號存數字，其他都是文字（`=` 開頭也不會變公式）。
  - 標題不含行尾標記和 `^編號`（拆到後面幾欄）；好幾行標題放同一格用換行接；內容一行一行放同一格，更深一層的 Tab 換兩個空白（格子裡看不出 Tab）；
    標記寫分類，沒分類寫「未分類」；代號用「、」接；隱藏寫「是」。
  - 內容那幾格自動換行、靠上；固定欄寬；第一列凍結、有篩選。XML 不能有的控制字元拿掉。
  - zip 只存不壓縮、檔案時間固定 1980-01-01：同樣的紀錄匯出來一個 byte 都不差（測試才比得了）。
- **頁面改名「格式」**（右上角鈕、頁標題）：最上面兩行「內建的匯入格式」「內建的匯出格式」；擴充一列寫「匯入：…」「匯出：…」，
  啟用的提醒照它提供的寫「會在你按『匯入…』時／匯出時／按『匯入…』或匯出時執行」。錯誤訊息裡的「右上角『匯入格式』」改成「格式」。
- 範例擴充加 `write`（`parse` 的反方向）和 `exportFormats`，版本 1.1.0、`engines` `^1.22.0`。

**為什麼**：
- `write` 回字串或 `Uint8Array`：使用者要「任何其他想要的格式」，xlsx、docx 本身就是 zip，只能回位元組。`ext-host.js` 把位元組轉 base64 再傳：parser 測試走 `child_process`，IPC 是 JSON。
- `data` 原文和拆好的都給：Excel 一筆一列要的是拆好的欄位；擴充自己拆會跟 D009（誰共用內容）不一樣，AI 寫的又不能 `require` daybook 的 `parser.js`（D056 禁用字）。
  原文留著給要照抄的（範例、daybook Markdown 自己重拆）。
- 跑完才跳存檔視窗：擴充出錯時不用白選一次位置。
- 自己寫 xlsx（使用者選的）：最小的 xlsx 是一個 zip（只存）裝 7 個 XML，`xlsx.js` 約 170 行，CRC 表自己算，不用裝套件。
- **用這台的 Excel 16 實際開過**（COM，唯讀、不顯示，2026-10-28）：
  - 造的測試資料：打得開，日期 46043 顯示 2026-01-21、`& < > "` 照原字、控制字元拿掉、`=SUM(A1)` 還是文字、兩張工作表都有篩選、第一列凍結。
  - 舊檔（只讀）匯出全部：打得開，「工作紀錄」646 列（645 張卡＋欄名）、「待處理」6 列。parser R8：330KB、8ms。
  - 這個檢查分得出壞檔：把 sheet1.xml 改壞（`<t>` 沒關）重新打包，Excel 直接開不起來。
- 下拉選單不違反 D025：D025 拿掉的是新增卡片時選狀態的下拉選單（要快）；匯出很少按，格式又會一直變多。E1「畫面上沒有下拉選單」改成不算這一個。

**沒採用的做法**：
- 裝 Excel 套件（exceljs 等）：多裝套件、打包變大（使用者選自己寫）。只做 CSV：沒有欄寬、換行、兩張工作表（使用者沒選）。
- 一排格式鈕：格式多了會很長（使用者選下拉）。另開「匯出格式」頁：使用者選一頁列兩種。
- 擴充的程式檔另開一個 `exportFormats: {}`：同一種格式匯入、匯出放同一個物件好對照（範例就是），id 也不會打架。
- `write` 回 `{ text }`／`{ bytes }`：多一層，AI 容易寫錯；看型別就分得出來。
- 檔名讓格式決定：存檔視窗本來就能改，格式只給副檔名。
- 檢查匯出的內容（空的、太大）：空檔不會壞任何東西，不擋。
- Excel 用共用字串表（sharedStrings）：省空間但多一個檔、多一套索引；直接寫在格子裡 Excel 打得開（實測），舊檔全部也才 330KB。自動欄寬：要量字寬，固定欄寬＋換行就夠。

**影響**：
- 新增 `src/shared/formats/xlsx.js`。`formats/index.js`：`EXPORT_FORMATS`、`exportData`；`daybook-md.js`：`write`、匯出 `weekday`。
- `extensions.js`：`checkManifest` 收 `exportFormats`（`readManifest`、`scan` 跟著帶）、`enabledExportFormats`、`startHost` 的 `write`；
  `ext-host.js`：`write`、`packed`，訊息的欄位 `text` 改名 `input`。
- `main.js`：`exportMd` 拆成 `exportRange`、`exportFile`、`pickSaveFile`（AI 試跑的「存一份看看」也用，D079），加 `exportFormatList`；IPC `export:formats`；
  `ext:list` 多 `builtinExport`、每個擴充的 `exportFormats`。`preload.js`：`exportMd` → `exportFile`，加 `exportFormats`。
- `index.html`：`#expFmt`、`#fmtBtn`「格式」、`#fmt` 標題和 `#fmtBuiltinOut`、說明頁 `extensions\` 那格（說明頁不能出現「匯出」，E40）；`app.js`：`fillExportFormats`、`renderExts`、`extWhen`；`style.css`。

## D079 請 AI 寫匯出格式：先選要寫匯入還是匯出，拿資料夾裡全部的紀錄試跑、預覽開頭、可以存一份打開看

- **日期**：2026-10-28
- **狀態**：已定案（「請 AI 寫」匯出格式也要、這次一起做，是使用者選的）；選匯入／匯出的單選鈕、prompt 字句、一次只寫一種、試跑拿全部的紀錄、「存一份看看」是 Claude 定的
- **相關**：D056、D059、D061、D065、D078

> 使用者（Claude 問「『請 AI 寫一個新的格式』現在只會寫匯入格式，匯出也要做這一套嗎」，推薦「之後再做」）：選「這次一起做」

**決定**：
- 「格式」頁「請 AI 寫一個新的格式」上面一行「要寫：○ 匯入格式 ○ 匯出格式」。換了之後 prompt、步驟說明的字跟著換（`data-kind`），上一次的結果收起來。
- **prompt**（`ai-ext.js` 的 `buildExportPrompt`）：daybook 的紀錄怎麼寫；`write(data)` 拿到什麼——例子是 `exportData` 對一份虛構的紀錄排出來的（D065；欄位改了例子跟著變），
  每個欄位一行說明；照使用者說的挑欄位、沒說的照原文、取捨先問；回覆格式同匯入（兩行分隔線）；`package.json` 只列 `exportFormats`；

- **檢查**（`checkReply` 多一個 kind）：其他照 D056，多一條「這次寫的是哪一種」：要有那一種的清單、不能有另一種。
- **試跑**（`tryExport`）：拿資料夾裡全部的紀錄（跟按「匯出全部」給的 `data` 一樣），在擴充程序跑每一種格式的 `write`（同真的匯出，D078）。
  預覽：拿了幾天、有沒有待處理；每一種格式是文字幾行（列開頭 30 行，多的寫還有幾行）或二進位檔，多大。還沒選資料夾就報錯。
- **「存一份看看…」**：每一種格式一顆，存的是試跑時主程序留著的那一份；存檔視窗、`--export-dir` 跟匯出共用（`pickSaveFile`）。
- 安裝照 D056（裝的是試跑過的那一份）；裝好的提示寫「之後在『匯出…』選這個格式」。
- 「複製給 AI」：試跑那步寫「拿我的紀錄試跑匯出沒通過」，不附檔案開頭（匯出沒有輸入檔）。

**為什麼**：
- 試跑拿全部的紀錄：最多的筆數、有待處理都跑過；在本機的擴充程序跑，程式先過禁用字的檢查，紀錄不交給 AI（同 D056）。
- 「存一份看看」：二進位檔在畫面上看不了；文字檔也常要用別的程式打開才知道對不對（例如 CSV 給 Excel）。
- 一次只寫一種：試跑要知道是選檔來拆還是拿紀錄匯出。兩種都要的分兩次請 AI 寫，或照範例自己合成一個。
- **實測**（2026-10-28，subagent 扮外部 AI，只給 prompt＋「我要 CSV 給 Excel 開：日期、星期、標題、內容、處理結果，待處理不要」；回答是 Claude 照常理代答的）：
  - 先列了 16 題要問（日期、星期寫法、標題留不留行尾標記、-> 那幾行算哪一格、要不要欄名……），「先問」有效。
  - 回的程式丟進 `checkReply`（kind export）→ `tryExport`（真的開擴充程序）：檢查過；fixture 3 天 5 列、舊檔（只讀）190 天 645 列、126KB 都跑過，BOM、引號、多行的格子都對。
  - 抓到 prompt 漏的兩件，補進 prompt（AI6 驗字句）：
    - 它遇到 `heads` 是空的就丟錯——prompt 沒說那天最前面沒標題的內容會是 `heads: []` 的一筆。fixture、舊檔剛好都沒有，所以試跑過了，但別人的紀錄可能有。
    - 它問 Excel 會不會把 `-` 開頭（`->` 那幾行）當公式、要不要加 `'` 擋。用這台的 Excel 16 開一份 CSV 量：`->…`、`-5`、`@abc` 照字顯示，`=1+1` 變公式，
      `+3` 變數字 3，前面加 `'` 的連 `'` 一起顯示出來。所以 prompt 寫「`=` 開頭會變公式；`->` 開頭照字顯示，不用處理（加 `'` 反而會顯示出來）」，免得 AI 為了擋公式改到原文。
  - 補了 prompt 之後沒有再派一次 subagent 驗 AI 照不照新的那兩句（未驗證）。

**沒採用的做法**：
