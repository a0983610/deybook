# 介面語言

這個主題的決定。索引與寫法見 `開發筆記.md`。

## D131 介面換語言：程式裡的中文原文當 key（L()），語言檔一個語言一個 JSON，請 AI 翻、貼回來檢查再裝

- **日期**：2026-11-02
- **狀態**：已定案（設定裡加語言、像擴充那樣給 prompt 請 AI 翻、看得到的字全部翻、只內建繁中、換了馬上重新載入，是使用者說的、選的）；
  原文當 key、語言檔的格式、回覆格式（代號＋翻譯一行一條）、HTML 自動換、哪些字算資料不翻、合併、頁面的樣子是 Claude 定的
- **相關**：D056、D059、D061、D062、D092、D098、D105

> 使用者：「設定裡增加一個語言調整 把UI介面上的文字做成能替換」「然後也是一樣像擴充 提供prompt 給AI貼回來擴充 就能增加支援語系」
>
> 使用者（Claude 問三件事後選的）：範圍「看得到的字全部」（畫面＋主程序跳出來的錯誤、對話框；給 AI 的 prompt 照中文；資料格式的字不翻）；
> 「只內建繁中，英文用 AI 做」；換了語言「馬上，畫面重新載入」

**決定**：
- **原文就是 key**：程式裡寫 `L('原文')`、`L('已隱藏 {n} 筆', { n })`（`src/shared/i18n.js`），查目前語言檔的翻譯，沒有就照原文。
  先存在表裡、之後才顯示的字用 `LK('原文')` 標記、顯示時 `L(x)`。主程序、shared 用 require；畫面用 `<script>` 載入同一份，字典由 preload 同步拿（`i18n:get`）。
- **HTML 的固定文字不用改**：`index.html`、`capture.html` 載入時 `translateDom` 一個一個文字節點、`title`／`placeholder`／`aria-label`／`alt` 查表換掉
  （空白縮成一個當 key；`code`、`kbd`、`pre`、`textarea`、`translate="no"` 裡的不換；`<template>` 的內容也換）。
- **收字**：`tools/i18n-keys.cjs` 收 `L()`、`LK()` 的原文和 HTML 的固定文字，寫成 `src/shared/i18n-keys.json`（照檔分段）；
  parser 測試 LN2 比它是不是最新的。`--audit` 列出還沒包 `L()` 的中文字串；故意不翻的那一行註解寫「不翻」，好幾行的用「不翻開始」「不翻結束」包住。
- **哪些不翻**（資料，翻了舊紀錄就對不上）：寫進檔案、parser 認的字（`[待回覆]`、`[標記:分類]`…）、固定的檔名資料夾、內建分類「未完」、
  匯出檔的內容（Markdown 第一行的標題、`## 待處理`、Excel 的欄名、工作表名稱）、給 AI 的 prompt、拿來比對的值（標記清單的「全部」「未分類」、`--existing` 比的按鈕字）、「繁體中文」這個名稱（語言自己的名稱，換到別的語言也要認得出來）。
  新東西的預設名稱要翻（新記事 N、外觀包「我的外觀」、存檔視窗的預設檔名）：找下一個號碼跟產生名稱用同一個 L() 模板，換語言後從新名稱的 1 編起。
- **擴充程序**（utilityProcess，拿不到主程序的字典）：開的時候用環境變數 `DAYBOOK_LANG_DIR`、`DAYBOOK_LANG_ID` 帶過去，自己 `locales.load`。
- **語言檔**：`%APPDATA%\daybook\locales\<名稱>.json`，`{ "daybookLocale": 1, "name": "English", "lang": "en", "strings": { "原文": "翻譯" } }`。
  只有字、沒有程式：不用「啟用」、不比版本；這版有、語言檔沒有的就是「缺的」，照中文顯示。用哪一個（檔名）記在設定檔的 `lang`（`--data-dir` 只記到關掉）。
- **語言頁**（齒輪「設定」→「自訂」→「語言…」）：介面的語言下拉選單（內建繁體中文＋語言檔），選了馬上換、畫面重新載入；語言檔清單（翻了幾條、缺幾條、壞掉的原因）、補翻缺的、刪除；
  「請 AI 翻一個新的語言」：填要翻成什麼 →「複製 prompt」→「開 Gemini／ChatGPT」→ 貼回 →「檢查」→「安裝並換成這個語言」。
- **prompt 與回覆**：prompt 列「代號 原文」（代號是原文 md5 的前 6 碼），AI 回「代號 翻譯」一行一條、第一行 `@lang 代碼`，每次最多 200 條、說「繼續」再回下一段。
  `↵` 是換行；翻譯頭尾要空白的地方寫 `␣`（一行一條留不住頭尾空白，被元件切開的片段英文會黏在一起）。
  檢查：認得幾條、裝了還缺幾條；代號對不上、`{…}` 跟原文不一樣的那條不收、寫原因，可以「複製有問題的給 AI」。不比 `<…>` 標籤：翻譯一律當字放（textContent、文字節點、屬性）。
- **串名單**：「、」「；」不單獨當 key（頭尾空白會被去掉，英文的 `, ` 變 `,`），用 `{a}、{b}`、`{a}和{b}`、`{a}；{b}` 兩兩接（`joinList`、`andList` 在 i18n.js）。
  安裝：同名（不分大小寫）的合併進原本的檔（新的蓋過、原本的留著），分好幾段貼、隔天補翻都走這條。

**為什麼**：
- 原文當 key：畫面上看到的字在程式裡 grep 得到（這個專案找東西都靠 grep 中文）；不用另外維護一份「代號 → 中文」的表。
  代價是同一個中文在兩個地方要翻得不一樣做不到（目前沒遇到），改了原文那條翻譯就失效——失效的照中文顯示、語言頁算得出缺幾條，補翻就好。
- 代號用原文的雜湊、不用流水號：跟順序無關，貼回來時不用知道當初 prompt 列了哪些；分好幾段回、只補缺的、隔天才貼都對得上。
- 一行一條、不用 JSON：回到一半被截斷，前面完整的那幾行照樣收得到；AI 也比較不會寫壞（JSON 的跳脫）。
- HTML 自動換：`index.html` 有 300 多句固定文字，每個都加屬性、改程式太多；文字節點查表就好，HTML 照原本的寫法維護。
- 語言檔一個 JSON、不像擴充一個資料夾＋package.json：沒有程式、沒有圖，一個檔給別人最方便；不比版本，daybook 改版不會整個不能用，只是多幾條缺的。
- 主程序換語言不重開：只換字典；畫面重新載入（跟換資料夾一樣用 `location.reload()`），記事本沒存的照 D105 在 beforeunload 暫存。

**實測**（2026-11-02，subagent 扮 Gemini／ChatGPT，只給 prompt）：
- 翻成 English：856 條分 5 段回（200×4＋56），代號、`{…}`、`↵` 全對；`checkReply` 收 855 條，擋掉 1 條是「<每一版不同的名稱>」翻成 `<a different name…>` 被當成標籤 → 拿掉標籤檢查，再跑 856 條全收。
- 裝起來開 daybook（螢幕外）截圖：主畫面、日曆、設定選單、語言頁、F1 快捷鍵表、外觀頁都換成英文、版面沒有壞；使用者的卡片照原字。
  外觀頁「You can changethe background image(faintly…) andthe…」黏在一起：被 `<b>` 切開的片段頭尾空白在一行一條的格式裡留不住 → 加 `␣`。
  同一個 subagent 當新對話、照新規則重翻 185 條片段：43 條用了 `␣`，合併裝起來那段變成「…image (faintly over the whole window) and the empty-state…」。
- 它提出、照改的：prompt 加「`#` 分段行不用回」「內建分類『未完』不翻」「句子和句子中間也要 `␣`」「為了接得通可以改句型」；語言頁自己的「語言代碼 {lang}；」接下一句也會黏，改成 `{a}；{b}` 兩兩接。
- 它提出、沒改的：同一個中文不同意思分不開（見〈沒採用的做法〉）；英文單複數（`1 entries`）；片段的另一半要看前後文才知道怎麼接（完整的 prompt 照順序列，比只給片段好）。

**沒採用的做法**：
- 每句編代號（`menu.import`）：要另外維護一份中文對照，程式裡看不到畫面上的字；這個專案一個人維護，grep 中文比較重要。
- 畫面所有文字節點都查表（連 app.js 動態加的也是）：使用者紀錄裡剛好有一模一樣的字（例如標題叫「設定」）也會被換掉。動態的字一律在程式裡 L()。
- 換語言不重新載入、直接重畫：app.js 有幾百個地方組字，每個都要重跑；重新載入最穩。
- 內建英文：使用者選了只內建繁中；改版加了字還要兩份一起改。
- 同一個中文、不同意思分開翻（例如「剪貼簿」頁籤 vs 系統剪貼簿、「標記」左欄 vs 卡片按鈕、外觀頁句子裡的「背景圖」vs 欄位名稱）：原文當 key 做不到，要另外加語境（`L('剪貼簿', '頁籤')` 之類）。
  扮外部 AI 實測時有提出來，目前英文翻成同一個字也看得懂，先不做。
- 檢查 `<…>` 標籤要跟原文一樣：翻譯一律當字放、不會變成 HTML，檢查沒有保護作用；實測反而把「<每一版不同的名稱>」翻成 `<a different name…>` 當成連結標籤擋掉。
