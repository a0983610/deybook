## D062 外觀包：換背景圖、空白時的插圖；一個資料夾＋package.json，右上角「外觀」一次啟用一個

- **日期**：2026-10-27
- **狀態**：已定案（換背景圖和空白時的插圖、用外觀包、亮暗共用一張、右上角加「外觀」，是使用者選的）；
  資料夾名稱、package.json 欄位、背景圖怎麼蓋、多淡、黑暗模式暗多少、插圖多大、啟用不用再確定，是 Claude 定的
- **相關**：D002、D016、D029、D034、D048、D051、D055

> 使用者：「設計可以放圖檔 客製化 UI介面的圖案」
>
> 使用者（Claude 問四件事後選的）：換哪裡「背景圖、空白時的插圖」（沒選程式圖示、按鈕圖示）；放法「外觀包」（一個資料夾＋package.json，跟匯入格式擴充一樣按「啟用」才用）；
> 亮暗「共用同一張」；入口「右上角新按鈕『外觀』」

**決定**：
- **放哪**：`<使用者資料>\skins\<資料夾>\`，正式是 `%APPDATA%\daybook\skins`；跟擴充一樣跟著 `--data-dir`、`--user-data` 走（D055）。「外觀」頁的「開啟位置」沒有就先建。
- **package.json**：`name`、`version`、`engines.daybook`、`displayName` 的規則跟匯入格式擴充一樣（D055，共用 `compatible` 和那兩個正規式）；
  `contributes.skin` 底下 `background: { image, opacity }`、`empty: { image }`，至少要有一種。`opacity` 是 0～1，沒寫是 0.12。
  圖要放在外觀包的資料夾裡（分享給別人才帶得走）、副檔名 png／jpg／jpeg／gif／webp／svg、檔案要在；不對就「壞掉」寫原因。
- **一次啟用一個**：設定檔記 `skin: 名稱`（停用寫 null）；`--data-dir` 時不寫設定檔，只記到關掉（同 D055）。啟用別的就換掉現在的。
  **按「啟用」直接換上，不用再按「確定」**；版本變了也不用再啟用一次。
- **背景圖**：一個 `#skinBg` 蓋在整個畫面上（`position: fixed`、`pointer-events: none`、`cover` 置中），用 opacity 調淡；
  z-index 5，在提示清單（12）、toast（10）、還沒選資料夾的卡片（15）、對話框（20）底下。黑暗模式加 `filter: brightness(0.6)`（`--skin-filter`，兩段黑暗的變數都寫）。
- **空白時的插圖**：「這天還沒有處理過的事」「沒有待處理的事」（含「（有隱藏的）」）那一行，字的上面、置中，最高 120px、最寬 60%。搜尋「沒有找到」不放；文字模式沒有那一行，也就沒有插圖。
- **圖怎麼到畫面**：主程序讀檔轉成 `data:` 網址（`skin:load`），CSP 加 `img-src 'self' data:`。畫面一開（`applySkin`，在第一次畫卡片前）、按啟用／停用時拿；
  啟用的那個壞掉、不見了就照原本的樣子開，不跳錯誤（頁面上寫原因）。
- **「外觀」頁**：外框跟說明頁一樣（Esc、點外面、✕）。上面一段說明＋外觀包資料夾＋開啟位置、清單（狀態四種跟匯入格式擴充一樣）；
  下面「做一個外觀包」三步＋照著改的 package.json（`skins.sample`，`engines` 填現在的版本）。
- 說明頁「設定與快取」那格多寫 `skins\`、settings.json 也記哪個外觀包。

**為什麼**：
- 蓋在上面、不是墊在底下：側欄、卡片、輸入框、待處理那塊都有自己的底色，墊在底下要全部改成半透明。蓋在上面只多一個元素；
  代價是字也被蓋一層，所以要淡（0.12）。用樹懶圖示當背景截圖看過淺色、黑暗，字都清楚。
- 黑暗模式暗一點：淡淡蓋一張亮的圖，深色底會變灰、字的對比變差。0.6 是 Claude 選的值，截圖看過。
- 用 `data:` 網址、不登記自訂協定：只有兩張圖，啟用時讀一次；自訂協定要在主程序登記，CSP 一樣要開。
- 不另外確定：匯入格式擴充按兩下是因為會跑程式（D055）；外觀包只有圖，主程序只讀 package.json 列的圖檔（限定在外觀包資料夾裡），什麼都不執行。
- 插圖限高 120px：已處理、待處理都空的時候有兩張，兩塊的高度跟著內容走（D029），太大會把輸入區擠小。

**沒採用的做法**：
- 跟擴充放同一個 `extensions\`、package.json 寫 `contributes.skin`：`checkManifest` 要求一定有 `importFormats` 和程式檔，只有圖的會被列成「壞掉」；
  要改就動到 D055、D056 定案的檢查，也會出現在「匯入格式」頁。分開放比較單純。
- 背景圖可以設位置、大小（例如只放右下角）：先只做鋪滿置中；要的話 package.json 再加欄位。
- 附一個範例外觀包（像 `examples/extensions/`）：沒有可以拿來分享的圖；頁面上有照著改的 package.json，S3 驗過照著放圖就能用。
- 程式圖示、按鈕圖示：使用者沒選。

**影響**：
- 新增 `src/main/skins.js`（`scan`、`load`、`sample`）；`extensions.js` 多匯出 `VERSION_RE`、`RANGE_RE`。
- `main.js`：`skinDir`、`skinEnabled`／`setSkinEnabled`、`scanSkins`；IPC `skin:list`、`skin:enable`、`skin:load`；`filesInfo` 多 `skins`；`files:open` 的 `skins` 沒有就先建。
- `preload.js` 的 `skinList`、`enableSkin`、`skinLoad`；`index.html` 的 CSP、`#skinBtn`、`#skinBg`、`#skin`、說明頁「設定與快取」；
  `app.js` 的 `emptyBox`、`applySkin`、`showSkin`、`renderSkins`、Esc；`style.css` 的 `--skin-filter`、`#skinBg`、`.skinEmpty`、對話框的選擇器多 `#skin`。
- 卡片清單空白那一行（`.empty`）要走 `emptyBox`，插圖才會跟著。daybook 跳第一碼時，使用者的外觀包會變「版本不合」（同 D055）。
- 圖很大（幾十 MB）時會整張轉成 base64 傳給畫面，沒有限制大小、沒量過多大會卡。
- 測試 S1～S3、E46。

**實測**（2026-10-27）：parser 286 條、e2e 254 條全過。故意拿掉 CSP 的 `data:`（插圖載不出來）、拿掉啟動時套用（重新載入那條）各紅 1 條；
拿掉 `pointer-events: none` 時背景圖擋住按鈕、E46 點不到「黑暗模式」，測試中斷；改回全綠。用樹懶圖示截圖看過淺色、黑暗、外觀頁。

**後續**：
- 2026-10-28：使用者覺得做外觀包太麻煩，加「用圖檔做一個」、去背、背景圖的位置和大小（〈沒採用〉的「設位置、大小」做了）→ 見 D066
- 2026-10-28：「外觀」頁的「做一個外觀包」三步＋照著改的 package.json 拿掉（`skins.sample`、S3 一起拿掉）→ 見 D068
- 2026-10-28：「外觀」頁每個外觀包多一顆「刪除」（先問一次、丟資源回收筒）→ 見 D073
- 2026-10-28：外觀包清單從「外觀」頁搬到「管理外觀包…」另一張（可以搜尋），頁上只留摘要 → 見 D085

## D066 外觀頁「用圖檔做一個」：選圖、去掉邊緣連著的底色、背景圖放鋪滿或九個位置

- **日期**：2026-10-28
- **狀態**：已定案（要能直接匯入圖檔、去背用「去掉邊緣連著的底色」、背景圖和插圖都能、位置是鋪滿＋九個位置＋大小，是使用者選的）；
  表單長相、預覽、預設值、資料夾名稱、gif／svg 不去背、建了就啟用，是 Claude 定的
- **相關**：D025、D055、D062

> 使用者：「製作外觀包 目前操作太麻煩 增加個能直接匯入圖檔 然後順便能處理成背景透明(可以的話) 順便增加能決定放圖檔的位置」
>
> 使用者（Claude 問四件事後選的）：位置是「畫面上圖出現在哪」（不是圖檔存哪）；去背「去掉邊緣連著的底色」（沒選 AI 去背、不做）；
> 範圍「背景圖、插圖都能」；位置選項「鋪滿＋九個位置＋大小」（選項裡寫明插圖照舊放在字上面、置中）

**決定**：
- **格式**：`contributes.skin.background` 多 `position`（`cover` 鋪滿＝沒寫時；或 `top-left`…`bottom-right` 九個位置）、`size`（不鋪滿時佔畫面寬幾 %，1～100，沒寫 30）。舊的外觀包不用改。
- **「外觀」頁加「用圖檔做一個」**：名稱；背景圖、空白時的插圖各一段「選圖…」（主程序開選檔視窗、讀成 `data:` 網址給畫面）、「不用了」；
  勾「去掉邊緣連著的底色」＋「差多少算底色」滑桿（0～128，預設 40）；背景圖再有濃淡（5～100%，預設 12%）、位置（「鋪滿」一顆＋3×3 九顆）、大小（5～100%，預設 30%，鋪滿時不能調）。
  縮圖墊棋盤格看得出哪裡透明；背景圖另有照視窗比例的小畫面預覽。按「建立並啟用」：主程序開新資料夾、存圖、寫 package.json、啟用（換掉現在的），表單清空。
- **資料夾**：名稱拿掉 Windows 不能用的字（沒填是「我的外觀」）；已經有這個資料夾、或別的外觀包的 name 是它，就接「 (2)」「 (3)」…；
  name 就用資料夾名稱，version 1.0.0、engines 填現在的版本，圖存成 `background.*`、`empty.*`。
- **圖**：沒去背照原檔存（不重新編碼，gif 照樣會動）；去背的存 png。gif（canvas 只拿得到第一格）、svg（向量圖）不能去背，旁邊寫出來。
- **去背**（`src/renderer/cutout.js`）：底色是邊緣一圈最多的那一格顏色（R、G、B 各 16 階一格）裡最多的那個顏色；從邊緣往裡擴散，R、G、B 都差 tol 以內的變透明；
  挨著底色、差 tol～2×tol 的照差多少變半透明，變半透明的不再往裡擴散。

**為什麼**：
- 去背不裝套件：CLAUDE.md 要裝新套件先問，使用者選了不用裝的。canvas 畫面就有；1600×1000（白底、邊緣柔化的紅圓）從勾下去到縮圖換好 102～125ms（量三次）。
  代價：背景複雜的照片去不乾淨；被主體圍住、不跟邊緣連著的底色（例如圈圈中間）不會去掉。
- 底色取「最多那格裡最多的顏色」、不取平均：T1 先寫的時候抓到——平均會被差一點點的顏色拉偏，tol 0 時連一模一樣的白都去不掉。
- 半透明的不往裡擴散：變半透明後 alpha < 128，「本來就透明的走得過去」那條會把它當成底色，從邊穿進主體（故意拿掉 T1 紅 2 條）。
- 位置用按鈕、不用下拉：D025 不用下拉選單（E1 守著畫面上沒有 select）；排成 3×3，看得出是哪裡。
- 大小用「佔畫面寬幾 %」：背景圖蓋在整個視窗上（`#skinBg` 是 fixed、inset 0），`background-size: N% auto` 跟著視窗寬縮放；
  小畫面預覽照視窗比例、用同一套 CSS（`placeBg`），縮小就是一樣的位置。
- 建了就啟用：使用者嫌麻煩，做好不啟用還要再按一次。做出來的就是普通的外觀包資料夾，要改照手寫的規則改。
- 手寫那段留著（改名「自己寫 package.json 做一個」）、補 position、size 的說明：分享給別人、想自己改的還用得到。

**沒採用的做法**：
- AI 去背：照片也去得掉，但要裝套件、下載模型；使用者沒選。
- 圖縮小了再存：會改到使用者的圖；先照原尺寸（D062 已知沒有限制大小）。
- 插圖也能選位置：使用者選的選項寫明插圖照舊。

**已知限制**：
- 拖「差多少算底色」停 150ms 重算一次；很大的圖要多久沒量（量過的只有 1600×1000）。
- 做好的外觀包頁面上不能再改，要改得自己改 package.json。
- 選圖、建立只用 e2e（`--pick-image`）驗過，真的選檔視窗沒點過。

**影響**：
- `skins.js`：`POSITIONS`、`SIZE`、`checkBackground`、`readImage`、`fromDataUrl`、`create`、匯出 `EXTS`；`readManifest`、`load`、`sample` 多 position、size。
- `main.js`：`--pick-image`（`argPickImage`）、IPC `skin:pick`、`skin:create`；`preload.js` 的 `skinPick`、`skinCreate`。
- 新增 `src/renderer/cutout.js`：`index.html` 在 `app.js` 前面載入（全域 `cutout`），測試直接 require。
- `app.js`：`BG_POS`、`placeBg`（`applySkin` 改用它）、`mk`、`mkPreview`、`mkProcess`、`mkPick`、`mkDrop`、`mkCreate`；
  `index.html` 的 `#mk`、手寫那段；`style.css` 的 `#skinBg, #mkScreenBg`（共用的背景圖樣式拆出來）、`#mk…`。
- 測試 S1、S2（補位置大小）、S4、T1、E49。

**實測**（2026-10-28）：parser 311 條、e2e 279 條全過。故意拿掉 cutout 的「半透明標成看過」紅 T1 2 條；讓 `placeBg` 一律鋪滿紅 E49 2 條；改回全綠。
截圖看過淺色、黑暗的表單和整個畫面（背景圖在右下、插圖在空白那行上面）。位置的 ↑↓ 原本跑去彩色的 emoji 字型，按鈕改用 Segoe UI Symbol 後跟其他箭頭一樣。

**後續**：
- 2026-10-28：背景圖改成可以好幾張，每張各自的位置、大小、濃淡 → 見 D067

## D067 一個外觀包可以放好幾張背景圖，每張各自選位置、大小、濃淡

- **日期**：2026-10-28
- **狀態**：已定案（「一個外觀包放好幾張」是使用者選的，不是同時啟用好幾個外觀包）；寫法、表單長相、疊的順序是 Claude 定的
- **相關**：D062、D066

> 使用者：「背景圖能選位置 大小 濃淡 多張嗎?」
>
> 使用者（Claude 問「一個外觀包放好幾張」還是「同時啟用好幾個外觀包」）：選「一個外觀包放好幾張」

**決定**：
- **格式**：`contributes.skin.background` 可以是一個物件（原本的，舊外觀包不用改），或陣列 `[ {…}, {…} ]`，每張各寫 `image`、`opacity`、`position`、`size`；後面的疊在上面。
  讀進來一律變成陣列；錯誤訊息寫第幾張（`background[1].position …`）；空的陣列算壞掉。「有：」那行寫「背景圖 N 張」。
- **畫面**：`#skinBg` 變成一個容器，一張圖一層 `.skinLayer`（`bgLayers`），每層自己的位置、大小、濃淡；黑暗模式的調暗放在容器上，整疊一起暗。
- **「用圖檔做一個」**：背景圖那段變清單。「選圖…」加一張（取消就不加），之後按鈕變「＋ 再加一張…」；每張一格（`#mkBgTpl`），寫「第 N 張」、
  各自的去背、濃淡、位置、大小、「不用了」（整格拿掉，後面的往前補號）；小畫面預覽一個，照順序疊全部。
- **存檔**：一張照舊寫成物件、存 `background.*`；兩張以上寫成陣列，存 `background.*`、`background-2.*`、`background-3.*`…

**為什麼**：
- 一張一層：CSS 一個元素可以疊好幾張 `background-image`，但 `opacity` 只能整個元素一起，每張的濃淡不一樣就要分開的元素。
- 一張還是寫物件：跟 D066 做出來的、手寫的一樣，看 package.json 的人不用管陣列；engines 填現在的版本，舊版 daybook 本來就會顯示「版本不合」。
- 「選圖…」直接加一張、不先開空格子：不會留下沒選圖的空格子，「建立並啟用」也不用判斷哪格是空的。
- 沒限制幾張：使用者沒說；每張都是 data: 網址傳給畫面，張數多、圖大會吃記憶體，沒量。

**沒採用的做法**：
- 同時啟用好幾個外觀包疊在一起：使用者沒選。
- 一個元素疊好幾張 `background-image`：濃淡沒辦法各自調。

**影響**：
- `skins.js`：`checkBackground` 多一個參數（錯誤訊息寫哪一張）；`readManifest` 的 background 一律是陣列、`parts` 寫張數；`load` 回陣列；`create` 吃陣列。
- `app.js`：`bgLayers`（`applySkin`、小畫面共用）；`mk` 改成一張圖一格 `{ box, … }`（`mk.bgs`、`mk.empty`）、`mkQ`、`slotOf`、`mkAlive`、`mkBgOf`。
  `index.html` 的 `#mkBgAdd`、`#mkBgList`、`#mkScreenRow`、`#mkBgTpl`；`style.css` 的 `.skinLayer`、`#mk .mkPos`（原本是 id）。
- `preload.js` 的註解；E46 的背景圖改看第一層。測試 S1、S2、S4、E49。
- 小畫面預覽在背景圖清單的最下面，張數多時要往下捲才看得到。

**實測**（2026-10-28）：parser 314 條、e2e 280 條全過。故意讓背景圖只畫第一張，E49 紅 2 條（小畫面、真的背景圖都只剩一層），改回全綠。
截圖看過兩張（左上 15% 70%、右下 30% 40%）的表單和整個畫面。

## D068 「外觀」頁拿掉「自己寫 package.json 做一個」那段

- **日期**：2026-10-28

## D073 「外觀」頁可以刪外觀包：先問一次，整個資料夾丟資源回收筒

- **日期**：2026-10-28
- **狀態**：已定案（要做、先問一次再丟資源回收筒是使用者說的或選的）；壞掉的也能刪、刪掉啟用中的一起停用、測試用 `--trash-dir`，是 Claude 定的
- **相關**：D051、D055、D062

> 使用者：「外觀包也加個按鈕可以刪除(才不用開位置手動刪除)」
>
> 使用者（Claude 問怎麼刪，另兩個是「直接丟回收筒、不問」「問一次再永久刪」）：選「問一次再丟回收筒」

**決定**：
- 清單上每個外觀包（**壞掉的、版本不合的也有**）多一顆「**刪除**」。按了收起來、底下展開「把「名稱」的資料夾（資料夾名稱）丟到資源回收筒？要救回來，到資源回收筒還原就好。」＋「確定刪除」「取消」——跟匯入格式擴充的「啟用 → 確定啟用」同一個樣子（D055）。
- 確定後整個資料夾用 `shell.trashItem` 丟到 Windows 資源回收筒，提示「已丟到資源回收筒：名稱」。
- 刪的是設定檔記的那個（啟用中，或啟用後壞掉的）就一起停用（`skin: null`），背景圖、插圖跟著拿掉；同名的還有另一個留著（name 重複）就不動設定。
- 用**資料夾名稱**找要刪哪個（`skinList` 多給 `folder`），只能刪清單上有的。

**為什麼**：
- 壞掉的也能刪：最常想刪的就是壞掉的；它沒有啟用／停用鈕。
- 用資料夾名稱：name 重複時，壞掉的那個跟好的同名（`scan` 會把 package.json 的 name 填進去），用 name 找會刪到好的那個。只認清單上有的，畫面送什麼路徑都刪不到外觀包資料夾以外。
- 一起停用：不清掉的話設定檔還記著那個名稱，之後放進或做出同名的外觀包會自己變成已啟用。
- 測試不碰使用者的資源回收筒：加 `--trash-dir <資料夾>`，刪除改成搬進那個資料夾（跟 `--open-log` 同一種做法，D051），還能驗資料夾整個都在（救得回來）。

**沒採用的做法**：直接丟、不問；問一次再永久刪——使用者選了問一次再丟回收筒。

**影響**：
- `main.js` 的 `skin:delete`、`argTrashDir`、`skinList` 多 `folder`；`preload.js` 的 `deleteSkin`。
- `app.js` 的 `renderSkins`（`data-folder`、刪除鈕、`.extConfirm`）、`skinAction`（啟用、停用、刪除都走這裡）；`style.css` 的 `.extConfirm` 選擇器多 `#skin`。
- 匯入格式擴充還沒有刪除鈕（使用者只說外觀包）。
- 測試 E46（壞掉的那列改成只有刪除鈕）、E53。`shell.trashItem` 本身沒有自動測試（測試走 `--trash-dir`）；沒用真的資源回收筒試過。

**實測**（2026-10-28）：e2e E53 全過；D070～D073 五處一起故意弄壞跑一次（這條的是刪掉啟用中的不停用），E53 紅 1 條，改回全綠。
