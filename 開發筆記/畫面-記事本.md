- 不走 Ctrl+Z 復原（`withUndo`）：打的字文字框自己復原得了；刪除使用者選丟資源回收筒，要救去那裡還原。

## D103 記事本左邊顯示行號：自動換行，行號照真的換行算、折下來的不標號

- **日期**：2026-10-29
- **狀態**：已定案（要行號、自動換行、折下來的不標號，是使用者說的或選的）；顏色、量法、行號字型跟內文一樣大是 Claude 定的
- **相關**：D054、D077、D102、D104

> 使用者：「記事本加上顯示行號」
>
> 使用者（Claude 問長的行：不換行左右捲（行號一行一個）／自動換行（折下來的不標號））：選「自動換行」

**決定**：
- 文字框左邊一欄行號，右對齊、灰色（淺色 `#6e7681` 是 Light Modern 的 `editorLineNumber.foreground`，暗色 `#858585` 是 Dark+ 的預設）；字型、行高跟文字框一樣，第一行對得齊。
- 長的行照舊自動換行；行號照真的換行（`\n`）算，空行也算，折下來的那幾行不標號。行號跟著文字框捲。
- 量法：文字框底下墊一層一模一樣的透明字（`#noteMirror`），一行一個 `div`，量每個 `div` 的 `offsetTop` 放行號。
  寬高照文字框的 `clientWidth`／`clientHeight`（扣掉捲軸），內距、字型、`tab-size`、`pre-wrap`＋`break-word` 都一樣，換行才一樣。
  打字、換一份、視窗大小或縮放變了（`ResizeObserver`）就重畫，同一個畫面更新只畫一次（`requestAnimationFrame`）。

**為什麼**：
- 文字框（`textarea`）量不到自己每一行折成幾行，只能照抄一份來量；D054 自動補完的灰字也是這樣疊（`areaGhost`），用 `clientWidth` 扣掉捲軸那點也是學它的。
- 墊在底下、不是疊在上面：D104 找到的字標顏色也畫在這層，透過透明底的文字框看得到，字還是文字框自己的，選字、打字都不受影響。

**沒採用的做法**：
- 不換行、左右捲：使用者選自動換行。
- 用 CodeMirror 這類編輯器套件：要裝新套件（CLAUDE.md 要先問），只為行號、找字不值得。
- 折下來的每一行也標號（照畫面上的行）：使用者選的範例是折下來的不標。

**影響**：
- `index.html` 的 `#noteEdit`、`#noteGutter`、`#noteNums`、`#noteWrap`、`#noteMirror`；`style.css` 的 `--line-num`、那幾個 id；
  `app.js` 的 `noteRender`、`noteLater`、`noteScroll`，`refreshNotes` 換了內容後重畫、`#noteEdit` 取代原本只藏文字框。
- 每次打字都重建整份的透明字和行號：幾千行以內沒問題；很大的檔（上萬行）打字可能會頓，沒量過。
- 墊底那層的字型、內距、換行設定要跟 `textarea` 的一般樣式（`style.css` 的 `textarea`）一樣，改一邊要兩邊一起改。
- 測試 E73。

**實測**（2026-10-29）：e2e 517 條全過。故意讓墊底那層不換行（`pre`）、行號不跟著捲，E73 紅 3 條；改回全綠。
E73 一開始內容太短，兩邊的 `scrollHeight` 都等於框高，「換行一樣」那條改壞了也不紅；改成填到會捲才比得出來。
截圖看過淺色、暗色：一行折成三行的只標一個號、後面的號對得齊。
沒測：縮放不是 100%；很大的檔打字的速度；完整跑。

**後續**：
- 2026-10-29：使用者要求跑完整跑（`--full`）：515 條全過（少的 2 條是只在安靜跑才有的 E41）。
- 2026-10-30：多游標的其他選取、游標也畫在墊底那層，`noteRender` 改成照切點一段一段包 → 見 D106。

## D104 記事本裡 Ctrl+F 找字：只找正在看的那份，右上角小框

- **日期**：2026-10-29
- **狀態**：已定案（記事本裡 Ctrl+F 是找字、只找正在看的那份，是使用者說的或選的）；框的樣子、不分大小寫、照字面找、按鍵、顏色是 Claude 定的
- **相關**：D054、D083、D093、D102、D103

> 使用者：「在記事本裡按 Ctrl+F 是在記事本裡找字」
>
> 使用者（Claude 問找哪裡：只找正在看的那份／全部記事一起找）：選「只找正在看的那份」

**決定**：
- 記事本開著時 Ctrl+F：文字框右上角跳出小框（照 VS Code 的 find widget）：輸入框、「2 / 5」、↑、↓、×；游標進輸入框、字全選。選著一段字（不跨行）就拿來找。
- 打字就找：不分大小寫、照字面（不是正規表示式），從游標（選著一段就是它的開頭）後面那個開始。找到的全部標顏色、目前那個深一點
  （淺色 `#a8ac94`、暗色 `#515c6a` 是 `editor.findMatchBackground`，其他的 `#EA5C0055` 是 `findMatchHighlightBackground`），找不到寫「沒有結果」。
- Enter／↓ 下一個、Shift+Enter／↑ 上一個，到底了繞回來；目前那個在畫面外才捲，捲到上面三分之一。
- Esc（在輸入框或文字框）、× 關掉：顏色拿掉，游標回文字框、選著目前那個。找的字留著，下次打開還在。
- 框開著時改了內容就重找，目前那個的順序不變（超過就最後一個）。

**為什麼**：
- 原本（D102）Ctrl+F 是回到日記搜尋，照 D083、D093「看不到搜尋框就先打開日記本」；使用者要的是在記事本裡找字。
- 標顏色畫在 D103 墊底那層的 `<mark>` 上：`textarea` 自己只能選一段，標不了全部找到的。
- 不分大小寫、照字面：找字多半是找一個詞；用 `RegExp` 的 `i` 而不是兩邊轉小寫，位置才不會因為轉小寫變長（例如 `İ`）而對歪。

**沒採用的做法**：
- 全部記事一起找：使用者選只找正在看的那份。
- 取代、分大小寫、整個字、正規表示式的開關：使用者沒提。

**影響**：
- `index.html` 的 `#noteFind`、F1 表（記事本那段加 Ctrl+F、「到處都能按」的 Ctrl+F 註明記事本裡是找字）；`style.css` 的 `--find-*`、`--widget-*`、`#noteFind*`、`#noteMirror mark`；
  `app.js` 的 `noteFind`、`noteMatches`、`noteFindCount`、`noteFindShow`、`noteFindRun`、`noteFindStep`、`noteFindOpen`、`noteFindClose`，`noteRender` 標 `<mark>`，Ctrl+F 那段、`HINTS`。
- 記事本開著時 Ctrl+F 不再回到日記；要回日記點頁籤列的日記本（或再點記事本）。E72 那條改成點日記本。
- 測試 E74。

**實測**（2026-10-29）：e2e 517 條全過。故意改成分大小寫，E74 紅 5 條；改回全綠。截圖看過淺色、暗色：標色跟字對得準、目前那個深一點。
沒測：F3／Shift+F3（沒做）；很長的檔裡捲到找到的那個；完整跑。

**後續**：
- 2026-10-29：使用者要求跑完整跑（`--full`）：515 條全過，E74 在真的視窗裡也過。
- 2026-10-30：加了取代（Ctrl+H，找字的框多一列）、跳到第幾行（Ctrl+G）→ 見 D108。
- 2026-11-03：加 F3／Shift+F3（照 VS Code，框關著也行）→ 見 D150。

  預設是第一個有字的行（拿掉檔名不能用的字、最多 40 個字），Enter 才建 `記事本\名稱.txt`，之後就跟其他份一樣；Esc 不存。名稱規則跟改名一樣（D102），也不能跟其他新記事同名。
- **沒存的暫存**：新記事、改過沒存的有名字的，停手 0.6 秒、換一份、存、×、離開記事本時寫進 `%APPDATA%\daybook\note-backup\<紀錄資料夾路徑的雜湊>.json`；

- **×**：有名字的照舊不問、丟資源回收筒（D102），改過沒存的**先把沒存的寫進去再丟**；新記事有字跳框問「存／不存／取消」（Esc、點外面＝取消），沒字直接關。
- **外面改了檔**：沒改過的換成檔案的內容（跟以前一樣）；改過沒存的留著畫面上的，存的時候蓋過去（不提醒）。

- 改名、取名按 Enter、Esc 之後游標回文字框接著打（點別的地方結束的不搶）。

**為什麼**：

## D106 記事本 Ctrl+D 多游標：自己在文字框上做，其他游標畫在墊底那層

- **日期**：2026-10-30
- **狀態**：已定案（要 Ctrl+D、自己做不裝套件、Esc 回到一個，是使用者說的或選的）；
  詞怎麼切、找的規則、哪些鍵每個一起、主要是最後選的那個、顏色、游標畫法，是 Claude 定的
- **相關**：D103、D104、D105

> 使用者：「vscode有個ctrl+D功能滿好用的也加進去」
>
> 使用者（Claude 問做法：自己做不裝套件（多游標要自己畫、自己處理打字和輸入法，最花工）／換成 Monaco（VS Code 的編輯器，要裝套件、放寬 CSP、exe 變大））：選「自己做，不裝套件」
>
> 使用者（Claude 問除了 Ctrl+D 還要哪些：整行與縮排／取代、跳行／多游標加碼（Alt+點、Ctrl+Shift+L）／頁籤與狀態列）：選「整行與縮排」「取代、跳到第幾行」（見 D107、D108）

**決定**：
- **Ctrl+D**：沒選字就選游標所在的詞；選著字就多選下一個一樣的（大小寫要一樣、照字面），從最後選的那個往下找，到底了從頭找，已經選了的跳過，全選了就不動；
  選到的在畫面外就捲到剛好看得到。好幾個游標都沒選字時按 Ctrl+D，每個都選它所在的詞。
- **詞**：用 `Intl.Segmenter('zh-TW', { granularity: 'word' })` 切，只算 `isWordLike` 的。中文切得出詞（「週會」「發票」「號碼」），英數字一串一個（`CWIN301000`）。
  從沒選字開始的（選到的是詞），之後找的時候英數字不能黏在英數字中間（`apple` 不找 `pineapple` 裡的）；中文不管（沒有空白隔開）。自己選的字照字面找、什麼都不管。
- **好幾個選取時每個一起**：打字、輸入法（選好字才補到其他游標）、Backspace、Delete（Ctrl＋是整個詞）、Enter、Tab、貼上（行數跟游標一樣多就一個游標一行，不然每個都貼整段）、
  複製、剪下（每個選取一行）、←→（Ctrl＋是一個詞）、↑↓（照真的換行、欄位一樣，折行不算）、Home（先到第一個不是空白的字，再按到行頭）、End，加 Shift 是拉選取。
  碰在一起、重疊的選取併成一個。
- **回到一個游標**：Esc（留最後選的那個）、點一下、Ctrl+A、Ctrl+Z／Ctrl+Y、PageUp／PageDown、Ctrl+Home／End、拖放；換一份、外面改了內容、找字選到找到的那個也是。
- **Ctrl+Z**：每個一起改的那一下包成一次 `insertText`，一次復原，復原後回到一個游標。
- **畫法**：文字框自己的選取是主要那個（最後選的）；其他的選取、游標畫在 D103 墊底那層：選取用 `.sel` 底色，游標是包住後面那一個字的 `span` 左邊一條 2px 的直線
  （在行尾包前面那一個字畫右邊、空行放一個空的 `span`），一秒閃一次。選取底色照 VS Code 預設的 `editor.selectionBackground`（淺色 `#ADD6FF`、暗色 `#264F78`，
  從本機 VS Code 的 `workbench.desktop.main.js` 查到），文字框自己的選取（`::selection`）也改成同一個顏色，主要的跟其他的看起來一樣。

**為什麼**：
- 文字框（`textarea`）只有一個選取，其他的只能自己記、自己畫、自己改；按鍵在 capture 階段先攔，Tab 縮排（`tabInsert`）、找字的 Esc 才不會再跑一次。
- 改字一律包成一次 `document.execCommand('insertText')`（從第一個改的地方到最後一個）：直接改 `value` 會把文字框的 Ctrl+Z 清掉。
  插進去之後文字框會捲到最後改的那裡，所以先記住捲到哪、改完捲回來，再照主要那個游標捲。
- 游標要包住一個字畫，不能放一個 0 寬的 `inline-block`：那會變成可以斷行的地方，折行跟文字框不一樣、行號就對歪；
  也不能用 U+2060（不斷行的 0 寬字），會讓原本能斷的地方不能斷。包住的 `span` 是一般 inline，不影響換行。
- 輸入法選字中的 `beforeinput` 不能取消，只能等 `compositionend` 拿選好的字補到其他游標；補之前先核對文字框的內容是「原本的、主要那個換成選好的字」，不是就回到一個游標，不硬補。
- 詞用 `Intl.Segmenter`：VS Code 預設的分隔字只有英文標點和空白（本機 VS Code 的 `workbench.desktop.main.js` 查到 `` `~!@#$%^&*()-=+[{]}\|;:'",.<>/? ``），
  全形標點不算，照這樣切中文會一整串選成一個（例如 README 的範例句會選到「雅琦問題：發票號碼XA34259000已於1」）；
  同一句用 Node 的 Segmenter 量過，切成「雅｜琦｜問題｜發票｜號碼｜XA34259000｜已於…」，E75 在 Electron 裡量到「週會要講」切出「週會」。
  「撥入單」這種字典沒有的會一個字一個字，要整個選就先自己選好再 Ctrl+D。
- 行頭用 `lastIndexOf('\n', p - 1)`：p 是 0 時起點會被當成 0，開頭就是換行的話找到它，行頭算成 1；E75 抓到的（↓ 第一個游標沒動），改成另外判斷（`noteLineStart`）。

**沒採用的做法**：
- 裝 Monaco（VS Code 的編輯器）、CodeMirror：使用者選自己做。
- Alt+點加游標、Ctrl+Shift+L 一次選全部一樣的、Ctrl+K Ctrl+D 跳過這個、Ctrl+U 退回上一個游標、Ctrl+Alt+↑↓ 上下加游標：使用者沒選（「多游標加碼」那個選項）。
- 選字中其他游標也跟著顯示選字的字（VS Code 會）：要自己畫選字的底線、還要跟著輸入法的游標動，先只在選好時補。
- ↑↓ 照畫面上折下來的行走：文字框量不到每個位置在第幾個折行，要一個一個量墊底那層；先照真的換行。
- Esc 留第一個游標（不確定 VS Code 留哪一個，沒查）：留最後選的那個，畫面不用跳。

**影響**：
- `app.js`：`noteMulti`（放在記事本的狀態那裡）、`selLo`、`selHi`、`noteWord`、`noteEditing`、`noteSels`、`noteMainIdx`、`noteSetSels`、`noteSingle`、`noteApply`、`noteEachEdit`、
  `noteLineStart`、`noteLineEnd`、`noteSeg`、`noteWords`、`noteWordAt`、`noteWordLeft`、`noteWordRight`、`notePrev`、`noteNext`、`notePosRect`、`noteReveal`、`noteAddNext`、`noteMove`、
  文字框的 keydown（capture）、beforeinput、composition、copy／cut／paste、mousedown；`noteRender` 改成照切點一段一段包（找到的字、其他選取、其他游標）；

**實測**（2026-10-30）：e2e 551 條全過。故意拿掉「不黏在英數字中間」，E75 從第二條起紅（選到 pineapple 裡的）；故意讓輸入法選好的字不補到其他游標，E75 紅 3 條；改回全綠。

## D107 記事本的整行操作、縮排照 VS Code：Alt+↑↓ 搬、Shift+Alt+↑↓ 複製、Ctrl+Shift+K 刪、Tab 縮好幾行、Enter 帶縮排

- **日期**：2026-10-30
- **狀態**：已定案（要這組功能、按鍵照 VS Code，是使用者選的「整行與縮排」）；空行不縮、4 個空白算一層、整行貼上插在上面、游標落點，是 Claude 定的
- **相關**：D105、D106

> 使用者（Claude 問除了 Ctrl+D 還要哪些，「整行與縮排」寫的是：Alt+↑↓ 整行上下移、Shift+Alt+↑↓ 複製整行、Ctrl+Shift+K 刪掉整行、沒選字時 Ctrl+C／Ctrl+X 是整行；
> 選好幾行按 Tab／Shift+Tab 一起縮排、退縮排；Enter 換行時帶上一行的縮排）：選了「整行與縮排」

**決定**：都照「選取碰到的那幾行」做（選到下一行行頭為止的，那一行不算，照 VS Code）；多游標（D106）時每一段一起；一次 Ctrl+Z 復原。
- **Alt+↑／↓**：那幾行跟上一行／下一行換位置，游標、選取跟著；碰到頂、底就不動（多游標時有一段到頂就都不動）。
- **Shift+Alt+↑／↓**：那幾行複製一份，↓ 游標跟著到下面那份，↑ 留在上面那份。
- **Ctrl+Shift+K**：刪掉那幾行（連換行；最後一行就連前面的換行），游標到接上來的那一行（刪的是最後一行就是上一行），欄位盡量一樣。
- **Ctrl+C／Ctrl+X 沒選字**：整行（連換行）；剪下是把那一行刪掉（同 Ctrl+Shift+K）。之後**沒選字貼上、貼的正好是整行複製來的字**，就插在游標那一行上面、游標跟著原本那一行
  （VS Code 也是這樣；認法是跟上次整行複製的字一模一樣）。多游標、行數跟游標一樣多時一行插一個。
- **Tab**：選取跨好幾行就每一行行頭加一個 Tab（空行不加），不然照舊把選取換成 Tab。**Shift+Tab**：每一行拿掉一個 Tab 或最多 4 個空白（`tab-size` 是 4），沒選字也是退這一行。
  縮排後選取開頭在行頭的留在行頭（還是選整行）。
- **Enter**：新的一行帶游標那一行行頭的 Tab、空白（只算游標前面那段）。

**為什麼**：
- 按鍵照 VS Code：使用者要的是「參考 vscode notepad++」，按鍵也是題目裡列的。Notepad++ 的 Ctrl+D 是複製整行（憑記憶，未驗證），跟 VS Code 的 Ctrl+D 撞，使用者指定 Ctrl+D 要 VS Code 的（D106），所以這組都照 VS Code。
- 空行不縮：避免留下行尾的 Tab（只有空白的行）。
- 整行貼上插在上面：不這樣的話，Ctrl+X 剪一行再到別的地方 Ctrl+V，會貼在那一行中間。
- 真的按 Ctrl+C／Ctrl+X 在沒選字時也會觸發 `copy`／`cut` 事件（截圖腳本裡量過），所以在事件裡做、不用另外攔按鍵。

**沒採用的做法**：
- 「多游標加碼」「頁籤與狀態列」：使用者沒選。
- Notepad++ 的按法（Ctrl+D 複製整行、Ctrl+Shift+↑↓ 搬行，憑記憶、未驗證）：跟 VS Code 的按法撞，只照 VS Code 一套。
- 自動縮排時，下一行空著再按 Enter 把剛剛帶的縮排拿掉（VS Code 的 trimAutoWhitespace）：沒提，先不做。

- 清單：`記事本\` 底下全部的記事和資料夾（幾層都可以），照名稱排（數字照大小、不分大小寫）、資料夾在前面；點資料夾展開／收起，展開了哪些記在這台電腦（`daybook.noteDirs`）。

- 上面一排**頁籤只放開著的**：照開的順序，新的接在最後面；開著哪幾份、哪個是預覽記在這台電腦（`daybook.noteTabs`）。新記事、改過沒存的一定開著；檔案在外面不見了又沒改過的拿掉（改過沒存的照 D105 留著）。

- 時間跟清單一起給：清單一重列就有新的時間，畫面不用另外決定什麼時候問。每次列清單多 stat 每份檔（非同步）；文件檢視釘很大的資料夾時多花多少沒量。

## D139 記事本不開不是 UTF-8 的 .txt（Big5、ANSI 存的）：提示、關掉那個頁籤，檔案不動

- **日期**：2026-11-03
- **狀態**：已定案（「打不開，跳提示」是使用者選的；提示的字、關掉頁籤、文件檢視照舊是 Claude 定的）
- **相關**：D102、D105、D116、D118

> 使用者：「把修先該修的 先修好 然後文字模式改成唯讀 只提供在卡片模式下編輯」
>
> 使用者（Claude 問：記事本讀到 Big5／ANSI 的 .txt 打不開跳提示／用 Big5 讀、存成 UTF-8）：選「打不開，跳提示」

**決定**：
- `notes.decode(buf, strict)`：記事本讀檔（`note:read`）用 strict——不是 `FF FE` 開頭的就用 `TextDecoder('utf-8', { fatal: true })` 解，解不了回 null，主程序回 `{ notUtf8: true }`。
- 畫面看到就提示「「名稱」不是 UTF-8 編碼，打不開：用記事本打開，「另存新檔」時編碼選 UTF-8，再開一次」（8 秒），關掉那個頁籤（`noteClose`），換到旁邊那份。
- 文件檢視讀 .md 照舊不 strict：只看不改，亂碼也不會毀檔。

**為什麼**：
- 原本照 UTF-8 硬讀（非 fatal）：Big5 的「中文」讀成 4 個 U+FFFD，改一個字按 Ctrl+S，原檔就被 `efbfbd…` 蓋掉、救不回來。
  D116 允許外面丟檔進 `記事本\`，「取代記事本」時把舊的 ANSI 筆記搬進來是合理的事。
- 不直接丟錯：`refreshNotes` 讀到一半丟錯的話，正在看的已經換成那份、文字框卻還是上一份的字，按 Ctrl+S 會把上一份的字寫進那個 Big5 檔。所以回一個標記，畫面自己關掉。
- 提示的字照匯入的 `readImportText`（「這個檔不是 UTF-8 編碼：用記事本打開，「另存新檔」時編碼選 UTF-8…」）。
- UTF-16 BE（`FE FF`）一樣打不開；UTF-16 LE（`FF FE`）照 D102 讀。

**沒採用的做法**：用 Big5 讀、存成 UTF-8（使用者沒選；Electron 帶不帶 Big5 解碼也沒量）。唯讀開：照 UTF-8 解是亂碼，唯讀也看不懂。
