# 開發筆記 · 畫面：截圖

這個主題的決定。索引與寫法見 `開發筆記.md`。

## D129 頁籤列加「截圖」：取代 Windows 剪取工具——daybook 自己框選、畫框和箭頭，存成編號、複製；要留的取名搬進 保留\，「清掉 N 天前的」整批丟

- **日期**：2026-11-02
- **狀態**：已定案（四個做法使用者選的；畫面、按鍵、顏色、預設值、編號記在設定檔、變透明不藏起來是 Claude 定的）
- **相關**：D002、D016、D030、D042、D052、D073、D083、D097、D102、D116、D122

> 使用者：「評估增加一個截圖功能 類似LINE桌面版 能管理不重要的截圖 或是確認要另外存下來的截圖
> 不重要截圖就檔名用編號就好」
>
> 使用者（看完評估）：「主要是想取代掉Windows 剪取工具 編號是我手動打的 定時會去清掉舊截圖 會需要畫框、箭頭 不需要快捷鍵結圖」
>
> 使用者選的（一次問四題）：存放位置「另外指定資料夾」、框好之後「原地畫完再存」（像 LINE）、留下來「取名，搬進「保留」子資料夾」、清舊截圖「一顆鈕清 N 天前的」。

**決定**：

- 頁籤列「文件檢視」下面多一格「截圖」（裁切的兩個直角）：中間換成截圖頁（`data-view="shot"`），**沒有自己的左欄**——左欄放日記本時那格收起來（不動 `data-side`，回日記照舊），放剪貼簿時照樣放剪貼簿（D112）。
- **「＋ 截圖」**：daybook 先變透明（`setOpacity(0)`）、等 150ms，抓每個螢幕（`desktopCapturer`），每個螢幕蓋一層無邊框、最上層的視窗（`renderer/capture.html`），底下是停住的畫面。
  拉框 → 框旁邊出現工具列：框、箭頭、復原（Ctrl+Z）、取消（Esc）、完成（Enter）。框好之後在框裡拉是畫，框外拉是重新框。紅色 3px。
  完成：框的那塊（實際像素）連畫的組成 png，存成 `<下一號>.png`、**同時複製到剪貼簿**（剪取工具也是截完就在剪貼簿），daybook 回來、提示存成幾號。
- **存哪**：截圖資料夾，位置記在設定檔 `shotDir`，預設桌面的 `截圖\`（使用者原本手動存的地方，編號接 638 下去）；截圖頁「變更資料夾…」換（原本的不動）。不在紀錄資料夾裡，備份（D097）不包。
- **編號**：資料夾裡最大的號、設定檔記的用過的最大號（`shotNo`）比較大的 +1——清掉了、換資料夾也不重用。只認資料夾最上層、純數字的 `.png`。
- **截圖頁**：保留的在最上面（照名稱），編號的照日期分段（修改時間那天）、新的在前；小標 `2026-11-02（一） · 5 張`。滑過出現複製、留下來、刪除（不問、丟資源回收筒，同記事本 D116），點縮圖放大看（Esc、點一下關）。
  外面用檔案總管動了跟著變（監看截圖資料夾）。
- **留下來**：名稱那格換成輸入框，Enter 取名搬進 `保留\<名稱>.png`（名稱規則照記事本 `checkName`，打了 `.png` 不再多加），Esc 取消；名稱不行提示、框留著。
- **清掉 N 天前的**：天數（預設 7，記在這台電腦）的那天（含）以前的**編號截圖**丟資源回收筒，保留的不動；先在同一列問一次「2026-10-26（含）以前的編號截圖 12 張丟到資源回收筒？」，按「確定清掉」才丟。1 是今天以外全部、0 是全部。
- 說明頁「檔案放在哪」多一列「截圖」（位置、開啟位置）；F1 快捷鍵表多一段「截圖」。

**為什麼**：

- 量了使用者原本的習慣（`Desktop\截圖`）：239 張 png，**全部是純數字檔名、400～638 連號**，10/05～11/02 四週，忙的日子一天 12～21 張，共 39.1 MB、平均 167 KB；1～399 已經清掉。
  執行中的是 SnippingTool，它的自動存檔沒開（`Pictures\Screenshots` 是空的）——使用者證實編號是自己手打的。編號、存放位置、清法都照這個習慣做，daybook 省掉手打和手動清。
- 放紀錄資料夾外面：一個月約 40 MB，放進去的話備份（整個資料夾壓 zip）越來越大；截圖是丟棄式的，不是紀錄。
- 自己框選（不是借 Win+Shift+S 再收剪貼簿）：使用者要的是取代剪取工具、要畫框箭頭。先試抓過使用者的兩個螢幕（1920×1080 兩個、縮放都是 100%、副螢幕在左邊 x=-1920）：專案裡的 Electron 就抓得到完整畫面，一次 114～185ms、`display_id` 對得上，不用裝新東西。
- 變透明、不藏起來（`hide()`）：藏起來之後最前面的程式換成別人，Windows 不一定讓新開的視窗拿到焦點，Esc、Enter 會按到別的程式（推論，未驗證）；透明的 daybook 還是最前面的程式。
- 組圖在蓋的那層做（canvas）：框、箭頭要畫進去，主程序沒有 canvas。主程序給的是 `toBitmap()` 的 BGRA，畫面轉成 RGBA；e2e 用左紅右藍的假螢幕驗沒有對調。
- 監看要比清單：這台電腦的 NTFS 會更新「上次存取時間」（`fsutil behavior query disablelastaccess` → `DisableLastAccess = 2`），畫面讀縮圖就觸發監看。量過：存取時間舊的三張，打開截圖頁 4 秒內重畫 2 次（新檔 0 次），e2e 的「確定清掉」那列被重畫收掉。
  改成收到事件先比「每張的相對路徑＋修改時間」，有變才通知畫面，量回 1 次（只有打開那次）。
- 蓋的那層不跟主視窗的縮放：原本以為 Ctrl+= 的縮放是同一個來源共用，給那層另開 session（`partition`）；拿掉之後 e2e E90（主視窗 125% 時量那層是 400×300、`devicePixelRatio` 1）照樣過，所以拿掉。

**沒採用的做法**：

- 借 Windows 剪取工具（Win+Shift+S），daybook 看剪貼簿有新圖就收：使用者要取代剪取工具。
- 全域快捷鍵、系統匣常駐：使用者說不需要快捷鍵；按截圖頁的「＋ 截圖」。
- 標題列放一顆隨時能按的截圖鈕：沒要求，先不做（從日記要先點「截圖」頁籤再按，兩下）。
- 截圖接到日記卡片上（`[圖:639]`）：會動到資料格式、匯出入，評估時建議第一版不做，使用者沒要。
- 打字、馬賽克、選顏色、滑過視窗自動框：使用者只要框和箭頭。
- 「留下來」跳存檔視窗存到別處：使用者選搬進 保留\。
- 開 daybook 時自動清：使用者選按鈕。

**影響**：

- 新檔：`src/shared/shots.js`（編號、日期、相對路徑的規則，純函式）、`src/main/shot.js`（抓螢幕、開蓋的那層、收結果）、`src/shot-preload.js`（那層只拿得到這一輪要的幾個，不給讀寫檔）、`src/renderer/capture.html／.js／.css`。
- `main.js`：設定檔 `shotDir`、`shotNo`（有 `--data-dir` 時只記在記憶體、資料夾在暫存的使用者資料底下，D016）；`shot:*` IPC、`shots:list`；`shot://local/<相對路徑>?v=<修改時間>` 給縮圖（只認 `shots.checkRel` 過的）；`files:open` 多 `shots`（沒有先建）；監看截圖資料夾（截圖頁第一次列清單才開始看）。
- 畫面：`index.html` 的 `#actShot`、`#shotPane`、`#shotBig`、CSP `img-src shot:`；`app.js` 的 `shotMode`、`setShotMode`、截圖那一段；`style.css`；`theme.js` 認 `daybook.view = shot`。
- 測試用參數：`--shot-image <png>`（不抓真的螢幕，拿這張當唯一的螢幕）、`--pick-shot-dir <資料夾>`；複製、刪除、開啟資料夾照用 `--clipboard-file`、`--trash-dir`、`--open-log`。
- 記事本、文件檢視、截圖頁都看不到日記標題列的「說明」「回顧」（原本就是這樣）。

**實測**（2026-11-02）：parser 463 條（SH1～SH5）、e2e 777 條全過（E89～E94，假螢幕走完拉框、畫、存、複製、留下來、清掉、換資料夾）。

**沒測**：真的螢幕上按一次（daybook 變透明 150ms 夠不夠、會不會被截進去；那層拿不拿得到鍵盤；兩個螢幕各蓋一層、在另一個螢幕拉框時這邊的框拿掉）、縮放比例不一樣的螢幕、一次清幾百張時 `shell.trashItem` 要多久、完整跑、打包出來的 exe。

## D130 截圖的工具列多「直線」；用哪個工具記在這台電腦，下次照上次的

- **日期**：2026-11-02
- **狀態**：已定案（記在 localStorage、按了就記、直線放在箭頭後面、兩端圓頭、不做按 Shift 拉水平是 Claude 定的）
- **相關**：D129

> 使用者：「截圖的時候框跟箭頭 留個記憶上次用什麼 然後加上拉直線」

**決定**：

- 工具列：框、箭頭、**直線**、復原、取消、完成。直線跟箭頭一樣從一端拉到另一端，紅色 3px、兩端圓頭，沒有箭頭。
- 按了哪個工具就記下來（`localStorage` 的 `daybook.shotTool`），下次「＋ 截圖」打開就是它；沒記過、記的不認得是框。

**為什麼**：

- 記在 `localStorage`：蓋的那層跟主視窗是同一個 session、同一個來源（D129 拿掉 `partition` 之後），存的地方跟主視窗的畫面設定（黑暗模式、縮放）一樣，關掉 daybook 再開還在；
  是這台電腦的習慣，不放設定檔、不跟紀錄走。

**沒採用的做法**：

- 按 Shift 拉成水平、垂直：沒要求，先不做。
- 用完才記（畫了才算）：按了工具沒畫就取消的情況，使用者多半還是想要那個工具；按了就記比較單純。

**影響**：`renderer/capture.html`（多 `#tLine`、`#tRect` 不寫死 `on`）、`capture.js`（`TOOLS`、`setTool` 記下來、打開時讀回來、`drawShapes` 的 `line`）、`index.html` 的 F1 那段。

**實測**（2026-11-02）：parser 463 條、e2e 安靜跑 783 條全過；E90 多四條：沒用過是框、直線多畫一條、直線畫進去而且沒有箭頭（尾端旁邊箭頭會蓋到的 (183,54) 還是藍的）、再打開照上次的（直線）。
故意拿掉讀回上次的、直線改照箭頭畫，E90 各紅 1 條；改回全綠。**沒測**：完整跑、真的螢幕上畫。

## D142 截圖單張不刪了，改成按右鍵「列印…」（縮圖、放大看都行）；保留那段可以收起來，預設收起來

- **日期**：2026-11-03
- **狀態**：已定案（拿掉單張刪除、保留的也拿掉、系統列印對話框、只放右鍵選單、保留可收合是使用者選的；選單只有列印一項、縮到一頁、收合記在 localStorage、印不出來才提示是 Claude 定的；真的印表機沒測）
- **相關**：D129、D134、D116

> 使用者：「截圖功能 的單張圖 把刪掉改成列印 刪掉只要靠整批刪掉就可以
> 保留的圖很多的話會不會造成看不到 新的暫存截圖?」
>
> 使用者選的（一次問三題）：列印用「系統列印對話框」、保留的「也拿掉」（保留的要刪用檔案總管）、保留那段「可收合」。
>
> 使用者（動手前追加）：「列印可以做在放大後的右鍵選單嗎」→ 問卡片上還要不要列印鈕：「只放右鍵選單 縮圖卡片上也可以一起有」（照這樣理解：卡片上不放鈕，縮圖、放大看按右鍵都出選單）。

**決定**：

- **單張不刪**：縮圖滑過只剩複製、留下來（保留的只剩複製）。編號的靠「清掉 N 天前的」整批丟；保留的 daybook 不刪，要刪用「開啟資料夾」在檔案總管刪。IPC `shot:delete` 一起拿掉。
- **右鍵選單 `#shotMenu`**：縮圖、放大看（`#shotBig`）按右鍵，只有「列印…」一項；樣子照常用的右鍵選單（D134），按右鍵的那張縮圖框起來（`.sel`）。正在取名（留下來的輸入框）不出。
  選單疊在放大看上面（`z-index` 21，放大看是 20）；Esc 先只收選單，放大看留著；從放大看印完放大看也留著。
- **列印**：主程序背景開一個看不到的視窗，只放這張圖（`shot://` 網址讀，帶修改時間），`@page` 邊界 10mm、圖 `max-width／max-height: 100%`——**縮到一頁裡、小圖不放大**；
  跳系統的列印對話框（`webContents.print`，不 silent），印完、取消都把那個視窗關掉。取消不提示；印不出來（`failureReason` 不是 cancel）才提示「印不出來：…」。
- **保留那段可以收起來**：小標換成 `<details>`／`<summary>`（左邊 ▸／▾），**預設收起來**；開著還是收著記在這台電腦（`localStorage` 的 `daybook.shotKeptOpen`），清單重畫照舊。
- 測試用參數 `--print-pdf <檔>`：不跳列印對話框，`printToPDF` 寫進這個檔。

**為什麼**：

- 會不會擠掉新截圖：量了截圖頁的排法——保留那段固定在最上面，縮圖一張約 167px 高（130＋名稱列）、一列 5～6 張（`minmax(200px, 1fr)`），
  保留到 30 張左右就 5～6 列、800px 以上，今天截的會被擠出第一個畫面。使用者現在的 `Desktop\截圖` 保留 2 張、編號 137 張（2026-11-03 量的），還沒發生。
- 收合用 `<details>`：鍵盤（Enter、空白鍵）開關、▸ 的樣子都是內建的，不用另外寫。
- 列印開另一個看不到的視窗、不在主視窗印：主視窗要印得靠 `@media print` 把畫面上其他東西全藏起來（元件多，還有外觀包蓋的背景圖 D062），之後加東西都要顧到列印；另開的視窗只有那張圖。
  這是 Claude 定的，沒有兩種都做出來比過。
  圖用 `shot://` 讀不寫暫存檔：protocol 登記在預設的 session，新開的視窗不給 `partition` 就是同一個。
- 縮到一頁：e2e 拿 60×3000 的長圖量，拿掉 `max-height` 印成 4 頁，加上是 1 頁。
- 選單項目寫「列印…」：會再跳一個對話框（Windows 的慣例是加 …）。

**沒採用的做法**：

- Windows 的「列印圖片」（檔案總管對 png 右鍵 → 列印，ShellExecute 的 print）：跳出什麼視窗看這台電腦 png 預設用哪個程式開，daybook 控制不了；使用者選了系統列印對話框。
- 卡片上放「列印」鈕：使用者說只放右鍵選單。
- 保留那段移到最下面：要找保留的得捲到底；使用者選可收合。
- 列印時的頁首頁尾（檔名、日期）：沒要求。
