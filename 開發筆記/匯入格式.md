# 匯入格式

這個主題的決定。索引與寫法見 `開發筆記.md`。

## D047 匯入格式做成模組：一種格式一個檔、自動認；之後開放外部擴充

- **日期**：2026-10-27
- **狀態**：已定案（做成外掛式的格式、這次只做第一階段、第二階段之後要做，是使用者說的）；介面、自動認格式的規則是 Claude 提的。兩階段都做了，第二階段見 D055
- **相關**：D018、D040、D044、D046

> 使用者：「目前我的格式匯入 設計成一個可以外掛的方式去支援匯入各種文字格式」
>
> 使用者：「外掛模組是想像vscode能夠去支援各種格式(評估)」「我的舊筆記 就是非標準格式 要另外支援匯入」
>
> 使用者（Claude 評估兩階段後）：「外掛先只做第一階段 然後也是要做第二階段(希望以後不只我一個人用)」

**決定（第一階段，這次做的）**：
- `src/shared/formats/` 一種格式一個檔，`formats/index.js` 登記。現在兩種：
  `daybook-md.js`（標準格式，D046）、`notepad-txt.js`（舊記事本，原本 `import.js` 的拆法搬過來，規則照 D008、D018、D019）。
- 每個格式模組給：`label`（名稱）、`hint`（一句話說長怎樣）、`extensions`（選檔視窗用）、`detect(text)`、`parse(text) → { days: [{ date, text }], todo }`。純函式、不碰檔案。
- 寫檔、已經有的日子跳過（D044）、Ctrl+Z 整批復原都在主程序／`import.js`，每種格式都一樣，格式模組管不到。
- 匯入時自動認：只有一種 `detect` 認得才用它；都不認得（錯誤訊息列出能匯入的格式）、兩種以上都認得就報錯，不猜（同 D018）。匯完的提示寫認成哪一種。
- 認法：舊記事本是「有日期行 `1/5`、`---年份---`、或『週報』那一行」；daybook Markdown 是「第一行有字的是 `# `，而且有 `## 日期` 或 `## 待處理`」。
  兩種不會同時成立：匯出檔每一行都是 `#`、`- `、空白縮排的 `- ` 或 `（沒有）` 開頭，不會有只寫日期的行。
- 選檔視窗的副檔名照登記的格式；兩顆匯入鈕（左下角、選資料夾卡片）都能匯所有格式，卡片上的字從「從舊記事本匯入…」改成「匯入…」。

**第二階段（之後做，像 VS Code 的擴充）**：
- 擴充放 `%APPDATA%\daybook\extensions\<名稱>\`：裡面的 `package.json` 宣告名稱、版本、相容的 daybook 版本、提供哪些格式，加上程式檔；丟進去、重開 daybook 就有，不用重新打包。
- 介面跟第一階段一樣（`label`、`hint`、`extensions`、`detect`、`parse`），內建的兩種格式不用改。
- 要另外做：讀 `package.json`、檢查版本相容；擴充放獨立程序跑（壞掉、跑太久不會拖垮 daybook）；檢查回傳的資料（日期格式、有沒有重複、是不是字串）；畫面列出裝了哪些擴充；測試。
- 風險：擴充的程式碼有使用者帳號的全部權限（VS Code 的擴充也沒有沙箱），只能裝信得過的；給別人用之前要想好怎麼提醒。

**為什麼這次只做第一階段**：目前只有兩種格式、使用者一個人用。第一階段先把介面定好，第二階段只是多一個「從哪裡載入」，格式本身不用動。

**沒採用的做法**：
- 設定檔描述規則（用 JSON 寫日期行長怎樣、哪行是標題）：舊記事本的年份標記、D009 這種規則寫不進去。
- 先在畫面上選格式再選檔：多一步；格式之間認得出來就不用問。
- `detect` 多傳檔名：現在兩種格式都只看內容；之後擴充需要再加（多傳一個參數不影響舊的）。

**影響**：
- 新增 `src/shared/formats/index.js`、`notepad-txt.js`；`import.js` 只剩 `planImport`（認格式、拆、跳過已有的）；`scripts/import-txt.js` 改用 `notepad-txt.js`。
- `main.js`：`pickTxt` → `pickImportFile`、`importTxt` → `importFile`、IPC `import:txt` → `import:file`；`preload.js` 的 `importFile`；`app.js` 的提示多寫格式名；`index.html` 兩顆鈕的說明。
- **加一種格式**：在 `formats/` 加一個檔、`index.js` 登記一行，parser 測試補 F1 和匯入案例；跟現有格式要認得出差別（不然會「兩種都像」）。
- 測試 F1、M1、E37（提示寫格式）、E38、E39。

**後續**：
- 2026-10-27：第二階段做了；擴充丟進去不用重開、要在說明頁按「啟用」才會跑 → 見 D055
- 2026-10-27：「兩種以上都認得就報錯」改成畫面上的匯入跳視窗問這次用哪一種 → 見 D058
- 2026-10-28：匯出也照這套做成外掛，`formats/index.js` 多登記匯出格式（`EXPORT_FORMATS`） → 見 D078
- 2026-10-28：內建的匯入格式只剩 daybook Markdown，舊記事本改成擴充、`notepad-txt.js` 刪掉 → 見 D084

## D055 匯入格式擴充（第二階段）：丟進 extensions 資料夾，在說明頁按「啟用」才會跑，跑在獨立程序

- **日期**：2026-10-27
- **狀態**：已定案（安全提醒用「逐個按啟用」、清單放說明頁、附教學範例，是使用者選的）；package.json 欄位、版本規則、10 秒、不用重開這些細節是 Claude 定的
- **相關**：D047、D016、D018、D023、D039、D048、D051

> 使用者：「之前說的到匯入格式外掛第二階段 可以做了吧?」
>
> 使用者（Claude 問三件事後選的）：安全提醒「逐個按『啟用』」、清單「說明頁加一段」、範例「附教學範例＋寫法說明」

**決定**：
- **放哪**：`<使用者資料>\extensions\<資料夾>\`，正式就是 D047 說的 `%APPDATA%\daybook\extensions`。
  `--data-dir` 時使用者資料在暫存區（D016）、`--user-data` 時在指定的資料夾，擴充都跟著走，測試不用另外加參數。
- **package.json**：`name`、`version`（x.y.z）、`engines.daybook`（只認 `^X.Y.Z`）、`contributes.importFormats`（每種 `id`、`label`、`hint`、`extensions`），
  可省的 `main`（沒寫跟 Node 一樣是 `index.js`）、`displayName`（沒寫用 name）。
  程式檔 `module.exports = { formats: { <id>: { detect, parse } } }`，介面跟內建的一樣（D047）。
- **相容**：第一碼一樣、而且不比 `^` 後面的版本舊。第一碼是資料格式不相容才跳（D039），擴充產出的就是每日檔的文字，第一碼變了就可能不對。
- **讀清單只讀 package.json，不跑擴充的程式**；打開說明頁、選檔、匯入時每次重讀，所以**丟進去不用重開**
  （D047 寫「重開 daybook 就有」，現在連重開都不用；同 D023 不做快取）。
- **啟用**：說明頁「匯入格式」一個擴充一列。未啟用的按「啟用」先在那一列展開提醒（可以讀寫你電腦上所有你能碰的檔案），按「確定啟用」才記下。
  記在 `settings.json` 的 `extensions: { 名稱: 版本 }`，版本變了就變回未啟用、要再按一次。有 `--data-dir` 時不寫設定檔（D016），只記到關掉。
- **狀態四種**：已啟用、未啟用、版本不合（寫要哪一版、現在哪一版）、壞掉（寫原因：沒有 package.json、不是 JSON、少欄位、找不到程式檔、name 跟別的擴充重複）。
- **怎麼跑**：擴充的程式只在匯入時跑。主程序用 Electron 的 `utilityProcess` 開一個獨立程序（`src/main/ext-host.js`），
  先跑完所有已啟用格式的 `detect`，選定了再 `parse`，匯完就關。一次超過 10 秒就把程序關掉、報「擴充「X」跑太久」；
  丟錯、程序自己結束也報錯並寫是哪個擴充。出錯就整批不寫。
- **認格式照 D018**：內建＋擴充裡剛好一種認得才用；兩種以上就報錯，寫是哪個擴充、提示可以到說明頁停用。
  都不認得、而且有還沒啟用的擴充，訊息補「有 N 個擴充還沒啟用」。
- **擴充拆出來的先檢查**（`import.js` 的 `checkParsed`）：日期要是真的 `YYYY-MM-DD`、不能重複，內容是文字，todo 是文字或 null；
  換行改 `\n`、有字的結尾補 `\n`（D018）。不對就整批不寫。內建的不過這關（parser 測試已經守著）。
- 匯完的提示寫「（格式名稱，擴充「顯示名稱」）」。
- **教學範例** `examples/extensions/daybook-example-dated/`：一行 `=== 2026-10-27 ===` 隔開每一天，附 `sample.txt`；不進 exe。寫法說明在 README〈寫匯入格式擴充〉。

**為什麼**：
- `utilityProcess`：Electron 給的子程序，跑 Node、可以直接關掉。worker_threads 跟主程序是同一個程序，擴充呼叫 `process.exit` 會把 daybook 一起關掉。
- 啟用要按兩下：使用者選的；擴充是一段程式，跟 VS Code 的擴充一樣沒有沙箱（D047 寫的風險）。
- 一次匯入開一個程序、用完就關：匯入很少按。用一般 node 量到「開程序＋跑 detect＋關掉」整個不到 0.6 秒（除錯腳本，515ms）。
- 打包後 `ext-host.js` 在 `app.asar` 裡，`utilityProcess` 開不開得起來只有打包版驗得到：2026-10-27 用 `electron-builder --win --dir` 打到暫存區，
  `--user-data` 指暫存資料夾開 `daybook.exe`，啟用範例、匯入 `sample.txt`，2 天和待處理都寫進去、內容跟範例拆的一樣，按下到寫好 147ms；`%APPDATA%\daybook\extensions` 沒被建。
- 規則有效的實證：寫範例時 `sample.txt` 的待處理寫了一行「週報」，舊記事本也認得（D019 的標示行），parser 測試 M2 直接報「同時像「舊記事本」和「日期分隔純文字」」。
  改的是範例檔，不是規則；範例的註解寫明要認得出跟別的格式的差別。

**沒採用的做法**：
- worker_threads：見上。
- `child_process.fork`（Electron 當 Node 跑）：Electron 建議用 `utilityProcess`。parser 測試是純 node，還是用 `child_process.fork` 開**同一支** `ext-host.js`（兩種都接），測丟錯、卡住、自己結束。
- 開 daybook 時就載入擴充：使用者沒按匯入，別人的程式也會跑；壞掉還會拖到啟動。
- 匯入時才跳視窗問要不要信任：使用者選了在清單裡逐個啟用。
- 用檔案雜湊記住信任了哪個：使用者選的是「名稱＋版本」。限制：程式改了、版本號沒改，不會再問。
- `detect` 丟錯就當作「不認得」繼續：壞掉的擴充會不知不覺；現在直接報錯，寫可以停用。
- 加 `--extensions-dir` 測試參數：擴充資料夾跟著使用者資料走，`--data-dir`、`--user-data` 就夠了。
- 加參數把 10 秒調短給 e2e 測：超時在 parser 測試用 0.8 秒驗（同一支 `ext-host.js`、同一個 `startHost`），e2e 不測超時，不多一個參數。
- `engines` 支援 `>=`、`~` 這些寫法：寫最少、夠用；其他寫法算壞掉，原因寫要怎麼寫。

**影響**：
- 新增 `src/main/extensions.js`（`scan`、`enabledFormats`、`startHost`、`compatible`）、`src/main/ext-host.js`、`examples/extensions/daybook-example-dated/`。
- `formats/index.js`：`pickFormat(text, more)` 多收擴充的格式；都不認得的錯誤帶 `unknownFormat`。
  `import.js`：`planImport` 改成 async、多一個 `ext` 參數；加 `checkParsed`。
- `main.js`：`extDir`、`extEnabled`／`setExtEnabled`、`scanExts`、`forkExtHost`；`pickImportFile` 的副檔名加上已啟用的；
  `importFile` 開／關擴充程序；`filesInfo` 多 `extensions`；`files:open` 的 `extensions` 還沒有就先建；IPC `ext:list`、`ext:enable`。
- `preload.js` 的 `extList`、`enableExt`；說明頁「匯入格式」（`index.html`、`app.js` 的 `renderExts`／`extAction`、`style.css`）；「設定與快取」那格的說明加 `extensions\`。
- 版本 1.10.0，範例的 `engines` 是 `^1.10.0`。**daybook 跳第一碼時，範例和使用者裝的擴充都會變「版本不合」**，範例要一起改。
- E40「不列匯出的檔」只看「檔案放在哪」「要完全移除時」兩塊：下面「匯入格式」列的內建格式說明本來就有「daybook 匯出的 .md」。
- 測試 K1～K4、F2、M2、E43。

**後續**：
- 2026-10-27：擴充清單從說明頁搬到右上角「匯入格式」頁；那頁另外可以請 AI 寫擴充，貼回來檢查、試跑過才裝 → 見 D056
- 2026-10-27：認格式「兩種以上就報錯」改成問使用者用哪一種；錯誤訊息裡的「說明」→「匯入格式」改成「匯入格式」頁 → 見 D058
- 2026-10-28：擴充也能提供匯出格式（`contributes.exportFormats`、程式檔的 `write`），`importFormats`、`exportFormats` 至少一種；擴充程序多一個 `write` → 見 D078
- 2026-10-28：「格式」頁可以刪擴充（先問一次、丟資源回收筒，刪啟用中的一起停用）→ 見 D081

## D056 匯入格式頁：右上角獨立一頁；請 AI 寫擴充，貼回來先檢查、拿使用者的檔試跑、預覽，按了才裝並啟用

- **日期**：2026-10-27
- **狀態**：已定案（「匯出」旁邊加一頁、整段搬過去、複製 prompt＋開 Gemini／ChatGPT、AI 寫的是擴充程式、檢查＋試跑＋預覽、通過後安裝並啟用但不匯入，是使用者說的、選的）；
  prompt 內容、回覆格式、禁用的字、測試參數是 Claude 定的
- **相關**：D055、D048、D051、D018

> 使用者：「在匯出旁邊增加一個 匯入格式頁面 然後把匯入格式 整段般過去」「設計一個複製prompt 然後按鈕開到web的gemini 或是GPT」
> 「pormpt說明如何使用 只要讓使用者將其他AI產生的資訊貼回來 就能跑匯入格式的轉入」「AI貼回來的內容 程式要驗證過 才能執行」
>
> 使用者（Claude 問三件事後選的）：AI 產生的是「擴充程式」（不是轉好的資料）；驗證「檢查＋拿你的檔試跑＋預覽」；通過之後「安裝並啟用，不匯入」

**決定**：
- 右上角「匯出…」旁邊加「匯入格式」，打開一頁（外框跟說明頁一樣，Esc、點外面、✕ 都能關）。D055 放在說明頁的「匯入格式」整段搬過來，說明頁只剩「檔案放在哪」。
- 同一頁下半「請 AI 寫一個新的格式」：
  1. 「複製 prompt」：prompt 寫明一天的紀錄怎麼寫、要回什麼、package.json 的樣子（`engines` 填現在的版本）、detect／parse 的介面、
     要認得出跟兩種內建格式的差別、不能用的字，最後留「我的檔案開頭」讓使用者貼幾十行。頁面上有「看 prompt 內容」可以展開看。
  2. 「開 Gemini」「開 ChatGPT」：用預設瀏覽器開 `https://gemini.google.com/app`、`https://chatgpt.com/`。網址固定在主程序，畫面只給是哪一個（同 D051）。
  3. AI 回一個程式碼區塊，用 `===== package.json =====`、`===== index.js =====` 兩行隔開兩個檔；整則回覆照貼（前後有說明、包在 ``` 裡、分成兩個區塊）也拆得出來。
  4. 「檢查並試跑…」：
     - **先檢查、不執行**：拆出兩個檔；package.json 照 D055 的規則（同一個 `checkManifest`），另外 name 只能英文小寫、數字、`-`（拿來當資料夾名稱）、
       main 要是 `index.js`、engines 要跟現在的版本相容；index.js 用 `vm.Script` 只編譯看語法；一行一行找禁用的字
       （`require`、`import`、`process`、`eval`、`Function`、`constructor`、`__proto__`、`globalThis`、`global`、`arguments`、`fetch`、`WebSocket`，註解裡也不行）。
       問題一次列完、寫第幾行，請使用者貼回給 AI 改。
     - **過了才選檔試跑**：程式寫到系統暫存區，跟真的匯入同一條路——已啟用的擴充（同名的舊版除外）＋這一個一起認格式（D018）、在獨立程序拆（D055）、`checkParsed`。
       要選中的就是 AI 寫的這個；什麼都沒拆出來也不收。跑完暫存的程式就刪。
     - **預覽**：拆出幾天、起訖、資料夾裡已經有幾天（匯入時會跳過）、待處理幾行，前 3 天每天最多 12 行；同名的會寫「會取代已經裝的…」；最後是提醒。
  5. 「安裝並啟用」：裝的是試跑過的那一份（主程序留著，畫面只給 token），不是框裡現在的字；框裡的字一改預覽就收起來、要重新試跑。
     裝到 `<擴充資料夾>\<name>\`（同名的裝回原本那個資料夾、只換 package.json 和 index.js），設定檔記下名稱＋版本（D055）。**不匯入**，要匯入自己按「匯入…」。
- 測試參數：`--clipboard-file <檔>` 複製不寫剪貼簿、寫進檔；`--open-log` 也記「開 Gemini／ChatGPT」的網址、不開瀏覽器。

**為什麼**：
- 擴充程式而不是轉好的資料：使用者選的。只要給 AI 幾十行樣本，全部紀錄不用交給 AI；轉換由程式做、結果固定，AI 改字、截斷的問題不會進到資料裡。
- 預覽畫面就是 D055「看過提醒再按」的那一步：使用者選了通過後直接安裝並啟用，提醒放在預覽最下面、按鈕上面。
- 禁用的字是「先檢查、不執行」能做到的程度：擋得住 AI 一般寫法裡讀寫檔案、連網路的程式（那些都要經過 `require`、`process`、全域物件、`fetch`），
  **擋不住刻意繞過的**（例如把字拆開再拼）。所以提醒照寫「擋得住一般寫法，擋不住刻意繞過的」，不說它安全。
- prompt 跟檢查用同一份禁用字清單（`ai-ext.js` 的 `BANNED`），兩邊不會對不上。
- 試跑走跟匯入同一條路（`planImport`）：試跑過了，真的匯入不會才發現跟別的格式撞、或拆出來的資料不對。實測 E44：範例還啟用著時，同一份 sample.txt 試跑直接報「分不出」。

**沒採用的做法**：
- AI 直接把整份紀錄轉成 daybook Markdown 貼回來：不跑別人的程式，但整份紀錄要交給 AI，AI 改了字驗不出來（使用者沒選）。
- 回覆用一個 JSON 包兩個檔：程式碼要跳脫成字串，AI 很容易寫壞；兩行分隔線人看得懂、AI 也照得了。
- 用 `vm` 開沒有 `require` 的環境跑 AI 的程式：`vm` 不是安全邊界，用 `constructor` 就逃得出去（Node 文件的說法，這次沒重新查，未驗證）；裝好之後也還是照一般擴充跑（D055）。
- 開網站時用網址帶 prompt（例如 ChatGPT 的 `?q=`）：兩個網站支不支援、會不會直接送出都沒查（未驗證）；先複製、貼上，兩個網站同一套步驟。
- 開網站時順便複製：使用者說的是「複製 prompt，然後按鈕開」，照兩步做。
- 同名的先刪掉整個舊資料夾再裝：舊資料夾裡可能有別的檔（例如範例的 sample.txt），只換那兩個檔就好。
- 通過後直接匯入那個檔：使用者選了不匯入。

## D081 「格式」頁可以刪擴充：跟外觀包一樣，先問一次，整個資料夾丟資源回收筒
