> 使用者（Claude 問圖示：剪貼簿／便利貼／兩張疊起來的紙）：選「剪貼簿」

**決定**：

  滑過、或用 Tab 選到時右上角才出現「編輯」「刪除」。
- 新增、編輯是同一張表單：標題（Enter 換到內文）、內文（Tab 縮排），Ctrl+Enter 或「儲存」存、「取消」收起來；標題、內文都要填，沒填提示、表單留著。

- 存在資料夾的 `暫存.md`，寫法照紀錄：沒縮排的行是標題、Tab 縮排的行是內文；內文中間的空行寫成只有一個 Tab 的行。
  外面用記事本改的也讀得懂：空白縮排（最多 4 個）也算內文、夾在內文中間的真空行留著、第一個標題前面的內文掛在一筆「（沒有標題）」上。
  外面改了檔，清單跟著變（D020）；正在編輯暫存時先不重畫，免得打到一半被洗掉。
- 搜尋、時間軸、匯出都不碰 `暫存.md`（它們只讀 `journal\` 和 `待辦.md`）。

**為什麼**：
- 不沿用紀錄的 `parser.js`／`entries.js`：要原封不動複製出去，紀錄的讀寫法會改到內文——`formatEntry` 把內文的空行丟掉（`parser.js:220` 的 `filter(l => l.trim() !== '')`）、
  標題行尾的 `[待回覆]` `^編號` 會被拆走、連續幾行「代號＋程式名稱」的標題會共用內文（D009）、沒縮排的「數字＋.」開頭算內文。
  另寫 `src/shared/snippets.js`，只學 `entries.js` 的做法：每個改動帶第幾筆＋那一筆的原文，對不上就丟 `Conflict` 不寫。
- 換行轉 `\r\n`：Windows 剪貼簿的文字慣例是 `\r\n`。查了 Chromium 原始碼：`ui/base/clipboard/clipboard_win.cc` 的 `ClipboardWin::WriteText` 把字串原樣（`CreateGlobalData` 用 memcpy）放進剪貼簿，
  不轉換行；只有網頁那條路（Blink 的 `SystemClipboard::WritePlainText`）在 Windows 會 `NormalizeLineEndingsToCrLf`。Electron 自己的 `electron_api_clipboard.cc` 那次抓不到（404），
  所以轉法用 `\r?\n` → `\r\n`：中間不管有沒有人轉過，結果都對、不會變成 `\r\r\n`。「格式」頁的「複製 prompt」（D056）沒跟著改，那份是貼進瀏覽器的。
- 新增放最前面：表單開在最上面，存了就在原地；暫存多半是最近要用的。檔案開頭有沒標題的內文（只有外面改才會有）時放在它後面，不然那段會被接進新那筆的內文。
- 編輯、刪除滑過才出現：左欄預設 180px，常駐兩顆鈕標題只剩一半；VS Code 側欄清單的按鈕也是滑過才出現。用 Tab 選到時也會出現（`:focus-within`）。
- 暫存卡片不用 `.card` 這個 class：`isBusy` 看 `.card.editing` 決定外部改檔時要不要重畫中間，暫存在編輯時不該擋住中間重畫，另外用 `snipBusy`。

**沒採用的做法**：
- 每張一顆「複製」鈕、左欄列標題中間編輯、只存在這台電腦、便利貼或兩張紙的圖示：使用者沒選。
- 沿用紀錄的條目格式（同一套 parser）：上面〈為什麼〉第一點，內文會被改到。
- 存成 JSON：外面用記事本改不方便；紀錄都是純文字（D004、D005）。
- 只填內文、標題自動拿第一行：使用者說「有標題跟複製用內文」，先兩個都要填。
- 拖拉排序、搜尋暫存、複製標題：使用者沒提。

## D094 暫存的內文可以寫日期符號 {yyyy.MM.dd HH:mm}：複製時才換成當下的日期時間

- **日期**：2026-10-29
- **狀態**：已定案（要做、`{yyyy.MM.dd HH:mm}` 這種寫法、卡片上照寫的顯示並標顏色、編輯時預覽，是使用者說的或選的）；
  認哪些符號、怎樣算符號、預覽的字、放在畫面那邊算，是 Claude 定的
- **相關**：D093

> 使用者：「暫存再加上能夠 取得日期的功能 例如我常常會複製貼上[2026.10.29 10:00 cm8] 這日期時間是要變動的 可能用個日期格式符號之類表達」
>
> 使用者（Claude 問寫法：`{yyyy.MM.dd HH:mm}`／`{now:yyyy.MM.dd HH:mm}`／固定的字 `{日期}` `{時間}`）：選「`{yyyy.MM.dd HH:mm}`」
>
> 使用者（Claude 問卡片上顯示：顯示符號、標顏色，編輯時預覽／直接顯示填好的樣子）：選「顯示符號、標顏色」

**決定**：
- 內文裡的 `{…}` 是日期符號：複製時換成那一刻的日期時間，檔案裡存的照寫的（`[{yyyy.MM.dd HH:mm} cm8]`）。
- 認的符號照 C# 的日期格式（大小寫有分）：`yyyy` 年、`yy` 年兩碼、`MM` 月、`M` 月不補零、`dd` 日、`d` 日不補零、`HH` 時（24 小時）、`H` 時不補零、`mm` 分、`ss` 秒。
- 怎樣算符號：大括號在同一行、裡面的英文字母整段都是上面的符號（同一個字母連在一起算一個，`MMM` 就不認）、至少有一個；
  其他字（標點、空白、中文、數字）照原樣，所以 `{yyyy年M月d日}` 也行。裡面有別的英文字、或一個符號都沒有的照原樣：`{0}`、`{ get; set; }`、`{hh:mm}`、`{}`。
- 卡片上照寫的顯示，符號那段（含大括號）用強調色；新增、編輯時內文有符號，底下即時預覽「複製時：…」。內文的提示字寫了這種寫法。

**為什麼**：
- 寫法、顯示：使用者選的。符號照 C#：使用者是 C# 開發者，`MM`／`mm` 的大小寫跟平常寫的一樣。
- 「整段都要是符號才算」：暫存很可能放程式碼片段，`string.Format("{0}")`、`{ get; set; }` 這種大括號不能被動到；只認大括號、不加前綴（像 `{now:…}`）是使用者選的短寫法，用這條規則擋掉撞到的情況。
  擋不掉的是剛好整段都是符號的，例如程式碼裡的 `{d}`、`{M}`——會被換成日、月（未遇過，記著）。
- 換字放在畫面（`src/renderer/datefill.js`），不放主程序：編輯時的預覽要即時算，畫面拿不到 `src/shared` 的 CommonJS；照 `cutout.js` 的寫法，畫面用 `<script>` 載入、測試用 `require`。
  複製時畫面先換好再交給 `snip:copy`，主程序照舊只轉換行（D093）。
- 時間用 `new Date()`（這台電腦的時區），跟畫面上的「今天」一樣是本機時間。

**沒採用的做法**：
- `{now:yyyy.MM.dd HH:mm}`、固定的 `{日期}` `{時間}`、卡片直接顯示填好的樣子：使用者沒選。
- 星期（`ddd`）、12 小時制（`hh`、`tt`）、只寫一碼的分秒（`m`、`s`）：使用者的例子用不到，先不認；要加在 `DATE_TOKENS` 加一行。
- 跳脫寫法（讓整段都是符號的大括號照原樣）：還沒遇到要的情況。

**影響**：
- 新檔 `src/renderer/datefill.js`（`dateSegments`、`fillDates`）；`index.html` 在 `app.js` 前面載入它；
  `app.js` 的 `snipBody`、`snipCard`（複製時 `fillDates`）、`snipEdit`（`.snip-preview`、提示字）；`style.css` 的 `.snip-date`、`.snip-preview`。
- 測試：parser DF1～DF3；e2e E66。

**實測**（2026-10-29）：parser 435 條、e2e 462 條全過。故意讓複製不換符號、拿掉符號的顏色，E66 各紅 1 條；改回全綠。
用 fixtures 複本開起來截圖看過淺色、暗色的卡片和編輯時的預覽。
沒測：真的剪貼簿、跨午夜／跨年的那一刻；縮放不是 100%；完整跑。

**後續**：

- 每次都收著、不記：會用之後就不用看了；記住展開要多一個設定，使用者沒提。

**決定**：
- 檔案：`剪貼簿.md` 裡「`#`＋空白（或 Tab）＋名稱」一行是分類，底下到下一個分類的卡片都屬於它；第一個分類前面的是沒分類的。
  `#123 單號`、`## 二級`、只有 `#`、縮排的照舊（標題、內文）。分類後面直接接內文（外面改的）掛在那個分類一筆沒標題的上面（同 D093 檔案開頭那筆）。
- 畫面：沒分類的放最上面、不寫名稱（沒有分類時跟原本一模一樣）；底下一個分類一行小字「▾ 名稱」＋它的卡片，都攤開。**點卡片照樣一下就複製**。
- 點分類那行（或 Tab 選到按 Enter）收起來，變「▸ 名稱 (幾張)」、卡片不畫；再點打開。收起來的記在這台電腦（`localStorage` 的 `daybook.snipFold`，照名稱）。
- 滑過、Tab 選到分類那行，右邊疊上 ＋ ✎ ×：
  - ＋：表單開在那一段最後面（下一個分類那行前面），存了放進那個分類。收著的先打開。
  - ✎ 改名：那行換成輸入框，Enter 存（錯了提示、框留著改）、Esc 取消、點別的地方也算 Enter。收著的改名照樣收著。
  - × 刪除：不跳詢問，分類那行拿掉，卡片（中間的空行跟著）搬到最上面沒分類那段的最後面；Ctrl+Z 復原（提示「剪貼簿刪除分類」）。
- 上面多一顆「＋ 分類」：清單最下面多一行輸入框，Enter 把「# 名稱」加在檔案最後面。「＋ 新增」放在沒分類那段的最後面（第一個分類那行前面）。
- 分類名稱一行、去頭尾空白，不能空白、不能跟別的分類同名。卡片的標題不能寫成「# 名稱」的樣子（存了會被讀成分類），提示。
- 調順序（D125）：分類那行也算位置——拖到別的分類、Alt+↑↓ 越過分類那行就換到那個分類。放在分類那行上面＝上一段的最後面；
  上一段收著也一樣（放進那個收著的分類最後面），搬進收著的分類就把它打開。Alt+↓ 越過收著的分類那行也是放進它的最後面。
- 有一張在編輯（含新增、分類改名）時，點分類那行不收、分類的 ＋ ✎ × 不做，提示先儲存或取消（同 D174）。

**為什麼**：
- 「不要點第二下」：使用者在意的是分了類以後，要先點開分類才點得到卡片。所以分類只是分段的小標題、預設都攤開；收起來是使用者自己要的，才多一下。
- 沒分類的放最上面、不寫名稱：沒建分類的人看起來跟原本一樣；舊檔（沒有「#」行）讀起來全部是沒分類的，不用轉換。
- 「#」後面要空白才算：照 Markdown 的標題寫法；`#123 單號` 這種標題（代號、單號）不能被吃成分類。只認一個 `#`：不多一層「## 子分類」的意思。
  使用者真的 `剪貼簿.md` 裡有沒有剛好是「# 」開頭的標題沒有看（不碰真資料），有的話升級後會變成分類（問存法的時候有講）。
- 收起來記在這台電腦、照名稱：跟記事清單資料夾的開／收（`daybook.noteDirs`）一樣不寫進檔案；照第幾個記的話，外面在前面插一個分類就全錯位。
  所以名稱不給重複（兩個同名會一起收）；外面改出同名的照樣讀得懂，只是一起收、一起開。
- 標題不能寫成「# 」開頭：存了讀回來會變成分類，那一筆的內文會掛到一筆沒標題的上面，等於壞掉；擋下來比偷偷改字好。
- 位置用 `{ cat, raw, at }`（第幾個分類、那一行的原文、那一段的第幾張），不用全部的第幾筆：
  「A 分類的最後面」和「B 分類的最前面」是全部的同一個第幾筆，分不出來。分類那行也帶原文驗，跟卡片一樣對不上丟 `Conflict`（D093）。
- 放在收著的分類那行下面算那個分類的最後面：收著時那一格夾在兩個分類那行中間，從上面搬進去想放最前面、從下面搬進去想放最後面，同一格兩種意思；
  照「收起來的是一整包，放進去就在最後面」一種講法，鍵盤和拖拉一樣。搬進去就打開，搬過去的那張看得到、鍵盤接著按得到。
- 刪分類卡片搬到最上面那段：使用者選的。分類最前面是沒標題那筆（外面改的）時不給刪：它只有內文，搬過去會接到別筆底下（同 D125 的理由）。
- 收／開整份重畫（收著的卡片不畫）：拖拉、Alt+↑↓（`reorder.js`）只看畫出來的，收著的不在畫面上就不會算錯位置；
  所以有一張在編輯時不給收，不然打到一半的被洗掉。
- ＋ ✎ × 用小圖示、疊在右邊：先做的是字的「＋ 改名 刪除」排在名稱右邊，截圖看到左欄 180px 時名稱擠成「私…」、收起來的那行名稱整個不見；
  照常用（D134 的 `.lp-tools`）改小圖示、疊在右邊（`--panel` 底色），名稱不被擠、滑過時版面不跳。
- `reorder.js`（D183）多三個可以不給的選項：`head`（分類那行的 class，算位置、不能拖）、`target`（放在第幾個前面要存成什麼）、`focus`（鍵盤搬完游標回哪）；
  「＋ 新增」多 `before`（開在誰前面）。不給就跟原本一樣，常用沒動。Alt+↑↓ 改成「放在上一個前面／下一個後面」，只有卡片時就是原本的 ±1。

**沒採用的做法**：
- 分段攤開不能收合、上面一排分類頁籤（換類要多點一下）：使用者沒選。
- 表單多一格「分類」：使用者沒選；放進分類靠 ＋ 和拖拉。
- 刪分類連卡片一起刪、有卡片不給刪：使用者沒選。
- 一類一個檔：使用者沒選；跨分類搬要同時改兩個檔、復原也要兩個一起。
- 分類調順序（拖分類那行）、分類裡再分類：使用者沒提。
- 收起來時卡片照畫、只是藏起來（不整份重畫）：拖拉、Alt+↑↓ 量位置時藏起來的卡片高度是 0、會被算在上面，要另外濾掉；整份重畫比較單純。
