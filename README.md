# daybook · 工作流水帳

> 版本：**1.21.0**（`package.json`；視窗標題會顯示，每次 commit 跳號，見 D039）
>
> 狀態：**第一版的功能都有了**（已處理／待處理、卡片輸入、搜尋、代號／事件時間軸），另加了搜尋／標題／內文的提示清單、換日快捷鍵、
> 黑暗模式、匯出 Markdown（日期區間、全部）、日曆模式、狀態列與 F1 快捷鍵表、匯入格式擴充、外觀包（背景圖、空白時的插圖）、已處理的標記清單（可以分類、自訂分類）；主題頁、依代號匯出、全域快捷鍵還沒做。

取代 `每日工作紀錄2026.txt` 那本記事本：照原本的寫法一天一天記，
工具負責把同一支程式、同一個主題的紀錄串起來——「記」跟記事本一樣快，「找」比記事本快。

## 文件分工

| 檔案 | 裝什麼 | 什麼時候改 |
|---|---|---|
| `README.md`（這份） | 產品說明：資料格式、功能、檔案、怎麼跑 | 格式／功能／檔案／指令變了才改 |
| `CLAUDE.md` | 開發規矩與流程 | 規矩變了才改 |
| `開發筆記.md` ＋ `開發筆記/` | **每個決定的來龍去脈**，依主題分檔，每條有編號（`D001`…），`開發筆記.md` 是索引 | 每做完一個決定就補 |
| `e2e測試.md` | 測試怎麼分層、有哪些案例、怎麼跑 | 加功能就加案例 |

**接手開發前先讀 `CLAUDE.md`。**

## 資料格式

### 每天一個檔

```
<資料資料夾>/                          ← 不在專案裡，位置在程式裡設定（D016）
├── 待辦.md                           ← 待處理：還沒處理完的事，不分哪一天（D019、D024）
├── 標記分類.json                      ← 標記的分類清單（自己加的），第一次加分類才建（D076）
├── journal/2026/10/2026-10-05.md    ← 已處理：一天一檔，檔名就是日期
└── topics/多統編發票.md               ← 跨好幾支程式的主題頁（需要才建）
```

為什麼不是一件事一個檔：見 開發筆記 D004。

### 一天裡面怎麼寫（跟舊 txt 一樣）

```
CWIN301000 撥入單 BUG
	Q1.備料單產生的單據，走自動核准按修改、刪除時請直接擋住
	Q2.查詢\來源單別，請將「請選擇」改為「全部」 (撥出單一起調)
雅琦問題：發票號碼XA34259000已於1/21作廢，但1/22又產生一次作廢的XML [待回覆]
	->雅琪問台應看看
```

| 寫法 | 意思 |
|---|---|
| 沒縮排的行 | **條目標題** |
| Tab（或空白）縮排的行 | 條目內容 |
| `->` 開頭 | 處理結果／原因，畫面上特別標示 |
| 標題行**最後面**的 `[待回覆]` | 狀態，現在只在待處理用（沒標就是待處理）。只認標題行尾；舊的 `[待處理]` `[完成]` 也認得（見 D006、D024） |
| 標題裡的 `^數字`（放在狀態前面） | 事件編號：已處理的事隔天又有後續時，今天另記一筆、用同一個編號串起來；按「+ 更新」時自動編（見 D022） |
| 待處理裡的 `->MM/DD …` | 待處理那一筆的進展，按「+ 更新」時自動帶日期（見 D024） |
| 標題行尾的 `[隱藏]` | 待處理先收起來不看，可以跟 `[待回覆]` 同時有：`週報 [隱藏] [待回覆]`（見 D026） |
| 標題行尾的 `[標記]` | 已處理的事還要注意、還沒完；跟其他行尾標記一起時寫成 `^編號 [隱藏] [標記] [狀態]`（見 D072） |
| 標題行尾的 `[標記:分類]` | 標記帶分類，例 `[標記:等客戶]`；冒號全形也認，寫回去是半形。只寫 `[標記]` 是未分類（見 D076） |
| 標題裡的 `#主題名` | 把這筆歸進 `topics/主題名.md` |
| 連續幾行只有「代號＋程式名稱」的標題，底下才接內容 | 這幾支程式共用那段內容（規則見 D009） |

### 工具自動抓的東西

不用另外標，從標題行抓（見 D007）：

| 抓什麼 | 例 | 用途 |
|---|---|---|
| 程式代號 | `CWMM3030`、`eWCH3050`、`TX_GetInvoiceNumber`（標題裡任何位置都算） | 同代號的條目自動串成時間軸 |
| 類型 | `BUG`、`BB`、`規格調整`、`新程式` | 篩選 |
| 人名 | `秀屏問題`、`看雅琦問題` → 秀屏、雅琦 | 篩「誰來問的」 |
| 工單號 | `Wc3620251231005` | 篩選 |

### 主題頁

```markdown
---
title: 支援開立多統編發票
status: 完成
---
摘要、規格重點、相關單號……
```

主題頁只放摘要；歷程不用抄，工具把所有標了 `#多統編發票` 的條目接在下面。

## 功能

### 第一版

1. **匯入**（D044、D047）：選資料夾的卡片上或左下角的「匯入…」，選檔案；自動認是哪一種格式（認不出就報錯；兩種以上都像就跳出來問這次用哪一種，D058）：
   - **daybook Markdown**：daybook 自己匯出的 `.md`，匯回來卡片一模一樣（D046）
   - **舊記事本**：`每日工作紀錄2026.txt` 那種，拆成每日檔，「週報」那行起搬進 `待辦.md`
   - **擴充的格式**（D055）：別人寫的格式放進擴充資料夾，在右上角「匯入格式」按「啟用」才會用；寫法見下面〈寫匯入格式擴充〉，也可以請 AI 寫（16）

   資料夾裡已經有的日子（或待處理）跳出來問一次：「加進去」是一筆一筆比，一模一樣的那筆不再加、其他接在那天最後面；「略過」是那些不匯、其他照匯（D063）。
   Ctrl+Z 整批復原；原檔只讀，不改
2. **已處理／待處理**（D024）：中間上面是這一天已處理的事，下面是待處理（不分哪一天，一直都在）。
   兩塊的高度跟著內容走、剩下的給輸入區（D029）；點標題列可以縮起來（D027）。
   **分隔線可以拉**（D074，像 VS Code）：左欄｜中間、已處理｜待處理、待處理｜輸入區（文字模式是兩塊中間那條），拉多大就多大、記在這台電腦；點兩下線還原，全部一起還原用「外觀」頁最上面的「還原預設大小」（D075）
   **刪除不跳詢問；按錯了按 Ctrl+Z 復原上一個卡片動作**（游標不在輸入框時，D028）
3. **卡片輸入**（D021、D025）：一打開停在今天。最底下的表單填標題（Enter 換到內文）、內文，
   按 **＋ 待處理**（Ctrl+Enter）或 **＋ 已處理（這一天）**（Ctrl+Shift+Enter）。
   **提示清單**（D054，像 VS Code）：打字時框下面列出以前寫過的——標題是整行標題和「代號＋程式名稱」（D031），
   內文是游標那一行的內文（這個標題底下寫過的排前面）；開頭或中間對得上都算，用過越多次越前面。
   **↑↓** 選、選中的用灰字預覽，**Tab** 帶入；按過 ↑↓ 之後 **Enter** 也是帶入（沒按過照舊換到內文／換行）；**Esc** 關掉、**Ctrl+Space** 叫出來
4. **待處理的卡片**：**待回覆**（點一下切換）、**+ 更新**（接在底下、帶今天日期）、**處理完 ↑**（整筆搬到上面正在看的那一天）、
   **隱藏**（收到最底下「已隱藏 N 筆」，點一下展開、可以取消隱藏）、編輯、刪除
5. **已處理的卡片**：**標記**、**+ 更新**、編輯、刪除
   - **標記**（D072、D076）：還要注意、還沒完的事。點「標記」底下冒出一排分類鈕：「未分類」、自己加的分類、「＋ 新分類」，點一個就標上
     （按鈕亮起來、寫「標記·分類」，行尾加 `[標記:分類]`）；「＋ 新分類」打名稱按 Enter，加進分類清單並標上。標過的再點「標記」可以換分類或「取消標記」。
     分類清單存在資料夾的 `標記分類.json`（還沒用到的分類也留著）；改名、刪除分類現在要直接改這個檔。
     左邊「清單｜日曆」旁邊的「**標記**」列出全部標記的（舊的在前），上面一排「全部｜未分類｜各分類」篩選鈕（後面寫筆數），點了只看那一類；
     每張可以直接「取消標記」；搜尋結果上也標「標記·分類」
   - 今天的：在同一筆底下加一行 `->…`
   - 過去的：在今天另記一筆，用 `^編號` 跟原本那筆串起來（D022）；原本那筆有標記的話，標記搬到今天這筆
6. **文字模式**：右上角切換，上下兩塊都變成原文直接打字、自動存檔（D020）
7. **日期清單／日曆**：左邊列日期，點了看那天；點過之後按 **↑ / ↓** 換到上一天／下一天（D070）；同一週一段底色，一週沒有、一週有（D071）。
   **Alt+← / Alt+→** 跳到前一個／後一個有紀錄的日子，**Alt+Home** 回今天（D033）。
   搜尋框底下切「清單」「日曆」（D036）：日曆一週從星期一開始、有紀錄的日子有點，‹ › 翻月；沒紀錄的日子也能點開來補記
8. **搜尋**（D023）：左上搜尋框（Ctrl+F），空白隔開的每個詞都要出現，標題和內容都算。
   打字時提示清單先列搜過的（搜越多次的越前面），再列內容裡的代號、程式名稱、人名（D032、D054）；
   按法跟新增表單一樣，按過 ↑↓ 的 Enter 是帶入再搜；有清單時 Esc 先關清單，再按一次才清掉
9. **時間軸**：點卡片上的代號標籤，列出那支程式所有紀錄；點 `^編號` 標籤，列出那件事每一天的紀錄。舊的在前
10. **匯出 Markdown**（D035）：右上角「匯出…」→ 填起訖日期（預設這週一到今天）按「匯出這段」，或按「匯出全部」（最後接待處理）；
    跳存檔視窗選位置。每天一個 `##`、每行標題一個 `###`（原文，含 `^編號`）、內容是清單（原文照抄）；
    這份檔就是標準匯出入格式，可以再匯回來（D046）
11. **黑暗模式**（D034）：右上角「黑暗模式／淺色模式」一鍵切換，記在這台電腦；沒切過就跟 Windows 設定。
    顏色照 VS Code Dark+，視窗標題列也跟著變暗；原生選單列藏起來，按 Alt 才出現
12. **快捷鍵說明**（D037）：最下面的狀態列寫游標所在地方能按的鍵；按 **F1**（或點狀態列右邊）看全部快捷鍵
13. **畫面縮放**（D042）：**Ctrl+=** 放大、**Ctrl+-** 縮小、**Ctrl+0** 還原，**Ctrl＋滾輪**也可以；整個畫面一起縮放、記住大小，
    狀態列右邊顯示比例（點一下還原）
14. **選資料夾**（D041）：還沒選、或原本的資料夾不見了，開起來畫面中間會請你按「選擇資料夾…」（不會一開就跳視窗）
15. **說明**（D048）：右上角「說明」，之後的說明都放這頁。現在有「檔案放在哪」：列出 daybook 在這台電腦放東西的地方（實際路徑，每個後面有「開啟位置」直接用檔案總管打開，D051）和怎麼完全移除：
    紀錄資料夾、設定與快取（`%APPDATA%\daybook`，解除安裝不會刪）、程式本身
    （可攜版每次開解壓到 `%TEMP%`、正常關掉會刪，當掉留下的下次開 daybook 會自動清（D050）；
    安裝版裝在 `%LOCALAPPDATA%\Programs\daybook`，另外會把安裝程式複製一份到 `%LOCALAPPDATA%\daybook-updater`，
    跟安裝檔一樣大，解除安裝會一起刪（D050）；解除安裝後 `%TEMP%\~nsu.tmp\Un_A.exe` 會留著，是所有 NSIS 解除安裝程式共用的暫存複本，可以直接刪）
16. **匯入格式**（D055、D056）：右上角「匯出…」旁邊的「匯入格式」打開一頁：
    - 內建的格式、擴充資料夾（「開啟位置」沒有會先建）、裝了哪些擴充（已啟用／未啟用／版本不合／壞掉的原因）；
      未啟用的按「啟用」先看提醒、再按「確定啟用」；已啟用的可以停用
    - **請 AI 寫一個新的格式**：「複製 prompt」→「開 Gemini」或「開 ChatGPT」，貼上 prompt 和自己檔案的開頭幾十行 →
      AI 回的那段程式碼貼回框裡 →「檢查並試跑…」：先檢查（不執行：格式、欄位、語法、不能用的字），過了再選要匯入的檔在獨立程序試跑、預覽拆出來的前幾天
      （別的格式也認得這個檔的話會寫出來，匯入時會問用哪一種）→
      「安裝並啟用」（不匯入，之後自己按「匯入…」）。沒通過就按「複製給 AI」貼回給 AI 改（D061）：
      複製的是哪一步沒過、每一條問題，AI 看不出原因的（detect 不認得、什麼都沒拆出來）多附檔案開頭 20 行有字的
17. **外觀**（D062）：右上角「黑暗模式」旁邊的「外觀」打開一頁，可以換**背景圖**（淡淡蓋在整個畫面上，點得穿過去）和**空白時的插圖**
    （「這天還沒有處理過的事」「沒有待處理的事」上面）。一組圖是一個外觀包，寫法見下面〈做外觀包〉；列出裝了哪些（已啟用／未啟用／版本不合／壞掉的原因），
    按「啟用」就換上、一次一個；黑暗模式用同一張，背景圖自動暗一點。
    不想自己寫 package.json：同一頁的「**用圖檔做一個**」（D066）選背景圖、插圖，要的話勾「去掉邊緣連著的底色」（白底、單色底的圖去得乾淨，可以調差多少算底色），
    背景圖調濃淡、位置（鋪滿，或四個角、四邊中間、正中間）、大小（佔畫面寬幾 %）；背景圖可以「＋ 再加一張」，每張各自調，後面加的疊在上面（D067）。
    小畫面先看放起來的樣子，按「建立並啟用」。
    最上面一段「**版面**」：「還原預設大小」一次還原拉分隔線調過的大小（D075；沒拉過時變灰）。
    不要的按「刪除」→「確定刪除」，整個資料夾丟到資源回收筒（壞掉的也能刪；刪掉啟用中的會一起停用，D073）

紀錄資料不在這裡：位置在程式裡設定，見 D016。

## 寫匯入格式擴充

像 VS Code 的擴充（D047、D055）：一個擴充一個資料夾，放進擴充資料夾就會列在右上角「匯入格式」頁，使用者按「啟用」才會跑。
照著改最快：`examples/extensions/daybook-example-dated/`（一行 `=== 2026-10-27 ===` 隔開每一天，附 `sample.txt` 可以直接試匯入）。
不想自己寫：同一頁的「請 AI 寫一個新的格式」，prompt 裡就是下面這些規格（D056）。

**放哪**：`%APPDATA%\daybook\extensions\<資料夾>\`（「匯入格式」頁的「開啟位置」會打開它，沒有就先建）。
`npm start -- --data-dir …` 開的時候，使用者資料在系統暫存區（D016），擴充資料夾也跟著在那，路徑看「匯入格式」頁。
不用重開 daybook：「匯入格式」頁每次打開、每次匯入都會重讀。

**package.json**

```json
{
  "name": "daybook-example-dated",
  "displayName": "範例：日期分隔純文字",
  "version": "1.0.0",
  "main": "index.js",
  "engines": { "daybook": "^1.10.0" },
  "contributes": {
    "importFormats": [
      { "id": "dated-txt", "label": "日期分隔純文字", "hint": "一行 === 2026-10-27 === 隔開每一天", "extensions": ["txt"] }
    ]
  }
}
```

| 欄位 | 意思 |
|---|---|
| `name` | 擴充的名稱，不能跟別的擴充重複；啟用記的是它 |
| `displayName` | 畫面上顯示的名稱（可省，省了用 `name`） |
| `version` | `x.y.z`；版本變了使用者要再按一次「啟用」 |
| `main` | 程式檔（可省，省了是 `index.js`） |
| `engines.daybook` | 只能寫 `^X.Y.Z`：daybook 第一碼要一樣、而且不比它舊（daybook 第一碼是資料格式不相容才跳，見 D039） |
| `contributes.importFormats` | 提供哪些格式：`id`（程式檔裡的名字）、`label`（格式名稱）、`hint`（一句話說長怎樣，認不出格式時列給使用者看）、`extensions`（選檔視窗用的副檔名） |

**程式檔**：`module.exports = { formats: { <id>: { detect, parse } } }`，介面跟內建的格式一樣，都只看傳進來的文字、不碰檔案：
- `detect(text)` → 是不是這種格式。daybook 會問每一種格式（內建＋已啟用的擴充），只有一種說是就用它；**兩種以上說是，畫面上的匯入會跳出來問使用者這次用哪一種**（D058）。
  所以跟內建格式像也沒關係，但不要寬到連別種檔都認，不然每次匯入都要選
  （daybook Markdown 第一行是 `# `；舊記事本有 `1/5` 這種日期行、`---2026---`、或剛好是「週報」的一行）。
- `parse(text)` → `{ days: [{ date: 'YYYY-MM-DD', text: 那天的內容 }], todo: 待處理的內容或 null }`，內容照每日檔的寫法（上面〈一天裡面怎麼寫〉）。
  格式不對就丟 `Error`，訊息會顯示給使用者看。

daybook 會再檢查：日期是真的日期、沒有重複、內容是文字；換行改成 `\n`。不對、丟錯、跑超過 10 秒，都整批不寫，提示寫是哪個擴充。
擴充的程式只在使用者按「匯入…」時，在另一個程序裡跑（`utilityProcess`）；它還是有使用者帳號的全部權限，**只裝信得過的**。

## 做外觀包

一個外觀包一個資料夾（D062），只有圖和 `package.json`、沒有程式。放進 `%APPDATA%\daybook\skins\<資料夾>\`（右上角「外觀」頁的「開啟位置」會打開它，沒有就先建），
打開「外觀」頁就會列出來。`--data-dir`、`--user-data` 開的時候跟擴充資料夾一樣跟著走，路徑看「外觀」頁。
「外觀」頁的「用圖檔做一個」做出來的也是這樣一個資料夾（名稱就是資料夾名稱，圖存成 `background.*`、`background-2.*`…、`empty.*`，D066、D067），可以照下面再改。

```json
{
  "name": "my-skin",
  "displayName": "我的外觀",
  "version": "1.0.0",
  "engines": { "daybook": "^1.14.0" },
  "contributes": {
    "skin": {
      "background": { "image": "background.jpg", "opacity": 0.12, "position": "cover" },
      "empty": { "image": "empty.png" }
    }
  }
}
```

| 欄位 | 意思 |
|---|---|
| `name`、`displayName`、`version`、`engines.daybook` | 跟〈寫匯入格式擴充〉一樣 |
| `contributes.skin.background` | 背景圖：`image` 圖檔、`opacity` 多濃（0～1，可省，省了是 0.12）、`position` 放哪（可省，省了是 `cover`：整張鋪滿、置中；或 `top-left`、`top`、`top-right`、`left`、`center`、`right`、`bottom-left`、`bottom`、`bottom-right`）、`size` 不鋪滿時佔畫面寬幾 %（1～100，可省，省了是 30）。好幾張就寫成陣列 `[ {…}, {…} ]`，每張各寫各的，後面的疊在上面（D067） |
| `contributes.skin.empty` | 空白時的插圖：`image` 圖檔。最高 120px |

`background`、`empty` 至少要有一種。圖檔寫相對路徑、要在外觀包的資料夾裡；png、jpg、gif、webp、svg。
「外觀」頁上沒有手寫的說明（有「用圖檔做一個」就用不到，D068）；要手寫或改做好的，照這裡。

## 怎麼跑

```
npm install                     裝 Electron 45.0.0；執行檔第一次啟動時才下載
npm start                       啟動；第一次開畫面上會請你選資料資料夾（存在 %APPDATA%\daybook\settings.json，見 D041）
                                已經開著的話不會開第二個，會把開著的叫到前面（D030）
daybook.cmd                     點兩下就開，跟 npm start 一樣；黑色視窗開完就關掉（D053）
npm start -- --data-dir <資料夾>  指定資料資料夾，不讀寫設定（開發、測試用，見 D016）
           --export-dir <資料夾> 匯出不跳存檔視窗，直接寫進那個資料夾（測試用，見 D035）
           --user-data <資料夾>  設定檔改放這裡，不碰 %APPDATA%\daybook（測試用，見 D041）
           --pick-dir <資料夾>   按「選擇資料夾」不跳視窗，直接當作選了它（測試用，見 D041）
           --pick-file <檔>      匯入選檔不跳視窗，直接當作選了它（測試用，見 D044）
           --pick-image <圖檔>   「外觀」頁「用圖檔做一個」的選圖不跳視窗，直接當作選了它（測試用，見 D066）
           --pick-format <格式名稱> 兩種以上格式都認得時不跳視窗，直接當作選了它；沒有這個名稱就當作取消（測試用，見 D058）
           --existing <加進去|略過> 匯入時資料夾裡已經有的日子不跳視窗，直接當作按了它；其他的字當作取消（測試用，見 D063）
           --open-log <檔>       「開啟位置」不開檔案總管、「開 Gemini／ChatGPT」不開瀏覽器，把路徑、網址寫進這個檔（測試用，見 D051、D056）
           --clipboard-file <檔> 「複製 prompt」不寫剪貼簿，寫進這個檔（測試用，見 D056）
           --trash-dir <資料夾>  「外觀」頁刪外觀包不丟資源回收筒，搬進這個資料夾（測試用，見 D073）
           --quiet-window        視窗開在螢幕外、不搶焦點、不上工作列，再開一次也不叫到前面（測試用，見 D052）
pack                            打包（點兩下 pack.cmd 也可以；見 D040、D043），產出到 dist\：
                                  daybook-版本號-portable.exe  可攜版：點兩下就跑，每次開要先解壓（約 7～10 秒）
                                  daybook-版本號-setup.exe     安裝檔：裝一次（只裝給自己、不用管理員），有捷徑、開得快
                                只清上次打包產生的東西，dist\ 裡其他檔案不動；資料資料夾跟 npm start 用同一份設定
                                （紀錄資料夾不要選在 dist\ 裡）
node tests/parser.test.cjs      解析層＋匯入層測試
node tests/e2e.cjs              e2e 測試，安靜跑：視窗在螢幕外、不搶焦點（見 e2e測試.md、D052）
node tests/e2e.cjs --full       e2e 測試，完整跑：真的開出視窗
node scripts/import-txt.js <舊檔.txt> --out <資料資料夾> --todo-from 週報
                                舊 txt 拆成每日檔，「週報」那行起搬進 待辦.md；
                                目標檔已存在就整批不寫（見 D018、D019）
```
